## 操作と描画の基準（コード確認）

| 項目 | 改修前の状態 | 改修後の比較 |
|---|---|---|
| アプリ一覧 | ストップウォッチ・設定・外部1〜3の5件。円弧に沿うアイコンと文字 | 項目の意味・順序と見た目を維持 |
| 一覧操作 | Aで循環、B/タップで決定、ドラッグ・慣性、先頭の下スワイプでホーム | 共通リスト移行後も維持 |

| 設定操作 | Aで循環、B/タップで決定。編集後は元の行、新しい入場は先頭 | 選択の復元と入場時の初期化を維持 |
| 設定編集 | 保存・キャンセル、ホームで破棄、輝度プレビュー、情報の統計表示有効化 | 既存の意味を維持 |
| 共通入力 | A+B 600msのホームが優先。外部起動確定中だけ例外 | 維持 |

描画の実装:

- `Renderer` が一覧・トーストを直接描く。設定トップは `SettingsLayer` が描き、配置は `ListLayout` の関数を利用する。
- 両リストの文字は `drawString` による直接描画。一覧はplanごとに `fitText` を実行し、省略結果の再利用や文字画像キャッシュはない。
- アイコンは44×44の埋め込みグレースケールマスク。円は毎回描き、アイコン合成結果の画像キャッシュはない。
- デジタル時計だけ時刻文字の内部RAMキャッシュを持つ。確保失敗・無効化時は直接描画する。
- 一つのFramePlan（容量32）で全レイヤーを解決し、消去後に描画・転送する。画面外の行は空矩形となる。
- 画面切替・トースト切替は全面再描画。ストップウォッチの固定要素は背景色まで塗り直す。
- ホストの差分テストは矩形モデルの検証。実フォント・M5GFX・実パネルのピクセル一致は実機検証で別に確認する。

## 今回の実機測定手順

ユーザーが実機測定と手動操作を選択。通常uploadを使わず、MultiFirmの `install-host` でota_0だけを更新する。
ツールによる全体バックアップと対象外領域の不変確認を記録し、終了時は通常版へ戻す。

1. 描画検証版でピクセル比較、キャッシュ寿命、容量超過からの復帰を確認する。
2. 測定版を起動し、実機・設定・画面サイズ・PM・メモリ・スロット走査の結果を保存する。
3. 一覧を上下にスクロールし、60秒集計の完全な操作窓を記録する。ホームへの遷移と起動操作は避ける。
4. 設定トップでAを繰り返し押し、選択変更を測る。現状スクロールはないためfpsではなく単発描画時間と入力遅延を評価する。
   情報画面等への往復による操作確認は性能窓と分ける。
5. 静止窓とメモリを記録し、通常版へ戻して起動を確認する。

画面上の統計オーバーレイは有効にしない。測定版はシリアル記録あり、実RTC・実スロット・保存済み設定を使用する。
現行の計測器は設定を `single-draw` に分類するため、設定のみを操作する完全な窓を使用する。
操作を止めた区間は連続fpsと分離し、全区間fps・休止回数・最大間隔も残す。
USB接続・シリアル開封中の測定なので、このログから電力や電池持ちを評価しない。
