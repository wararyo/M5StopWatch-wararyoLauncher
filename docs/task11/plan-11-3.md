# 11-3: Noonishの背景・秒の丸・多色背景上の描画

作成日: 2026-09-28。状態: 計画（未実装）。上位仕様は[作業11](plan.md)、依存は[11-1](plan-11-1.md)・[11-2](plan-11-2.md)。

## 1. 到達点

Noonishを4つ目として登録し、針の延長線に追従する4色背景と背景を明るくした秒円を描く。
操作・期限・情報条件はAnalogと共通、保存状態は独立とする。10秒境界の背景更新と丸だけの更新を分ける。

## 3. 背景色の判定

中心から画素へのベクトルをp、時針・分針の単位方向をh・mとし、cross(h,p)とcross(m,p)の符号の組み合わせを4色へ対応させる。
画素中心で判定し、符号0の扱いを固定する。角度順に色を並べ直さない。
参考画像の領域内部からRGB565パレットを定義し、参考時刻の代表点と色の対応をテストへ固定する。

AAは絶対座標に対する固定サンプル方式等を初期案とする。境界付近だけ同じ2×2サンプルを使い、各サンプルの最終領域色を合成する。
針一致・反対向きで境界が重なる場合も、2本の線を順次ブレンドして二重の縁を作らない。
均一な行区間は連続塗りし、境界だけ画素合成する最適化を検討する。最適化前後の色は一致させる。
全画面画像を持たず、backgroundAt(x,y)相当の純粋関数を背景と秒円で共用する。

## 4. 秒円と前景の合成

秒円の各画素でAA済み背景色Bに白を混ぜた色Lを求める。白混合率は初期50%、円の被覆率cで`blend565(L,B,c)`相当の合成を行う。
中心位置の1色で円全体を塗らず、境界の両側を明るくする。毎回背景を復元し、再描画で明るさが蓄積しないようにする。
秒円は最後に描く。別の前景と重なるAA縁は描画済み画素へ合成し、描画順を維持する。

日付・情報ラベル・アイコンは背景を抜いた被覆マスクとして復元済み画素へ合成する。
Forestの一定色を背景にする文字・アイコン処理をそのまま流用しない。
最初に既存フォントAPIの透明描画・背景読取をローカル実装で確認し、不足する場合は文字単位／表示欄単位の小さなマスクを使う。
`VlwGlyphs`は現状MaxGlyphs=16の時刻用なので、日本語を含む一般ラベルへそのまま適用しない。既存の計測・省略・代替フォントを維持する方法を選ぶ。
マスクの上限・寿命を明示し、確保失敗時は直接合成等の代替か既存begin失敗復元を使う。不透明矩形を出す退避は採用しない。

## 5. 背景damageと被覆

背景キーは量子化した時分、有効性、viewportで構成し、秒だけの変化を含めない。
背景が変わる10秒境界では初期実装で可視文字盤領域全体をframe.damageへ宣言する。
FramePlanとパネル転送は最終的に1矩形へ統合するため、小領域を多数登録するだけで転送量が減るとは仮定しない。
背景が不変なら丸・文字等の旧新領域だけを更新する。

opaqueAreaは背景を全画素描く範囲だけを返す。一覧から露出した帯も復元対象に含め、Forestのクリップ変化処理を参照する。
背景→日付・情報→針→中心円→秒円を守り、広い背景が小damageに接しただけではdamageを拡張しない。
無効時刻は10:07相当の固定背景とし、針・秒円を隠す。有効化時は再計算する。

## 6. 実装順序

1. 背景純粋関数、4色対応、境界AAとホストテスト。
2. 小さな診断ケースで文字・アイコン合成方式を確定。
3. 共通制御と前景を接続し、秒円を明色化。
4. 背景・被覆のdamage、独立保存、4番目の登録を接続。
5. 基本画素比較と通常／描画検証版ビルドを確認。

## 7. 検証と完了条件

- 参考時刻の4色、軸・中心、針一致／反対／追越し、角度の一周。
- 1色内／境界上／境界を跨ぐ秒円、同じ入力の再描画一致。
- 背景だけ変わる際も同じ文字列の輪郭を正しく復元する。
- 丸だけの更新で背景キーが変わらず、10秒境界の同時更新も一致する。
- 日本語・省略ラベル・アイコンに黒矩形や単色の縁がない。
- 部分被覆の増減、無効時刻の出入り、Analogとの往復で残像・設定混同がない。

`11-3-validation.md`に結果、文字合成方式、マスク量、白混合率を記録する。
最適化は基準描画との一致を保ち、背景全体更新の負荷は11-5へ引き継ぐ。
