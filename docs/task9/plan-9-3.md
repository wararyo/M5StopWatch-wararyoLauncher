# 9-3: 設定トップを共通リストへ移行

2026-09-23。状態: 実装・ホスト検証済み。実機確認は9-5。前提: [9-2](plan-9-2.md)の共通リスト。
結果は[9-3の検証記録](9-3-validation.md)。
[親計画](plan.md)に従い設定トップの見た目・スクロールを変更する。実機検証は9-5。

## 1. 画面と状態

設定トップは「日時・輝度・消灯時間・情報・戻る」の順を維持し、各項目に専用の安定IDを定義する。
配列添字からSettingsViewへの加算変換をやめ、IDから遷移先を明示的に対応付ける。
輝度と消灯時間の保存済み値は行ラベルに引き続き表示する。
行データの生成は設定側が担当し、共通部品には整形済みの表示名を渡す。

SettingsScreenが設定専用ListControllerを、SettingsLayerが設定専用ListViewを所有する。
アプリ一覧のインスタンスと状態・キャッシュを共有しない。
設定メニューの選択・スクロールはListControllerだけを正とし、編集画面のcursorと分ける。

| 境界 | 状態の扱い |
|---|---|
| 設定へ入場 | 先頭行を選択し、先頭行が中央となる配置から開始 |
| メニュー→編集/情報 | 選択と位置を保存し、慣性・ドラッグ・更新期限を停止 |
| 保存/キャンセル/情報から戻る | 選択行とスクロール位置を復元し、保存成功時だけ表示値を更新 |
| 戻る行 | 設定を退場し、ランチャー一覧の選択・位置を維持 |
| A+Bホーム | 未保存編集・プレビューを破棄し、入力・慣性・期限を解除 |
| 再入場 | 過去のスクロール位置を復元せず、先頭へ初期化 |

## 2. 見た目と操作

- アプリ一覧と同じ円弧・行高・選択色・ドラッグ/慣性を使う。設定行はアイコンなし。
- アイコンなしの文字起点は9-2の共通規則を使用する。設定用のダミーアイコンは作らない。
- B/タップで決定、Aで循環し、選択行を見える位置へ移す。
- 先頭で下へドラッグしてもホームへ戻らず、先頭位置へ収束する。
- 編集画面の日時・輝度・消灯時間の入力、保存失敗、統計有効化等は既存仕様を保つ。

SettingsLayerはメニューならListView、編集/情報なら既存の要素群をplan/paintする。
SettingsViewの切替はScreenIdが変わらないため、Rendererの画面切替判定だけに依存してはいけない。
この段ではメニュー↔編集/情報の切替時に全面再描画を明示的に要求し、両方の履歴を無効化する。
同じメニュー内の選択・スクロールでは差分描画を維持する。

## 3. 期限・活動状態・消灯

Screenへ `active()` 相当の問い合わせを追加する（既定false）。
SettingsScreenはメニューのドラッグ/慣性中だけtrueを返す。
ScreenManagerは、内蔵画面が表示中ならその活動状態、ホーム/一覧ならランチャー側の状態を返す。
隠れたランチャーの慣性が設定の活動状態や描画期限へ混ざらないようにする。

SettingsScreenの `nextUpdate()` / `tick(now)` はメニュー中だけListControllerへ委譲する。
静止・編集・退場後はINT64_MAX。遅れたアニメーションは現在時刻の状態へ進め、古いフレームを再生しない。
RuntimeのGPIO通知・100ms追跡・USB期限・最低1tick待機は変更しない。
消灯中は表示期限で起床せず、復帰時は経過時間に応じて整列し、不要な期限を残さない。
アニメーションだけで無操作タイマーを延長する新仕様は導入しない。

## 4. 診断とテスト

現在のRenderDiagnosticsは全体のdragging/animatingでモードを分類する。
設定リストの状態を隠れたAppListModelへコピーして測定器を動かす実装は避ける。
構成側から「画面種別＋操作種別」の計測情報を渡し、ランチャースクロール・設定スクロール・設定単発選択を区別する。
9-0の単発選択（A約2回/秒、描画平均10.157ms）と、新設するスクロールの値を別々に比較できるようにする。
9-4でRendererを分離しても、この計測情報はアプリ側に残す。

ホストで確認する項目:

- [x] A/Bとタップ、選択循環、スクロール中のヒットテスト、慣性停止時の誤決定抑止。
- [x] 編集/情報から元の行・位置へ復帰、新規入場時の先頭初期化。
- [x] 保存値のラベル更新、キャンセル/ホームによるプレビュー復元、保存失敗時の編集継続。
- [x] 設定スクロールの期限でRuntimeが描画すること、終了後の期限解除、消灯中の表示停止、復帰時の収束。
- [x] 戻る/ホーム後に設定の活動状態や期限が残らないこと、一覧先頭の下スワイプだけがホームへ戻ること。

描画診断へメニュー↔編集、途中位置からの退場/復帰、トースト、長いラベル、アイコンなしを追加する。
実機の差分/全面比較と見た目、性能・メモリは9-5へ送る。ホストテストを実機描画合格の代わりにしない。

## 5. 実装順序と完了条件

1. 設定の行IDとデータ生成を用意する。
2. メニューの操作を専用ListControllerへ移し、編集cursorと分ける。
3. ListViewへ描画を移し、メニュー切替の消去・無効化を接続する。
4. 期限・活動状態・計測分類を接続してホスト回帰を確認する。
5. 旧設定メニュー用の描画・ヒットテスト・配置互換関数を削除し、3構成をビルド・検査する。

完了条件: 両画面が同じView/Controllerを使い、設定にリスト描画や慣性の複製がなく、
期限・復帰・編集・保存のホスト検証が通る。9-2で用意した文字キャッシュの恩恵も同じ経路で受ける。
成果物はコード・テストと `9-3-validation.md`。未実施の実機確認を9-5へ明記する。
