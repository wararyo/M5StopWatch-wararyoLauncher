## 1. 目的と範囲

- Digital WatchFaceの文字をアンチエイリアス付きのフォントへ改善する。
- バックグラウンド実行中のアプリから、アプリの識別情報と表示を希望する整形済み文字列を受け取る。
- タッチ長押しで、選択中の文字盤のバリアントを切り替える。
- タップの意味はWatchFaceが決める。一覧を開く要求を返せるが、タップ操作の実装は必須にしない。上スワイプによる一覧表示はシステムが提供する。
- Forest WatchFaceを追加し、Digitalと切り替えて利用できるようにする。
- Digitalは常時、Forestは残量30%未満または充電中にバッテリー残量を表示する。ヒステリシスは設けない。
- 一覧をWatchFaceの上にかぶせて描く。文字盤には一覧を開く進捗を渡し、遷移時の文字盤の表現は文字盤側で決める。

## 3. 表示と操作

### 3.1 確定要件と暫定値

前節までの範囲と「アプリ側で文字列を整形する」責務は確定要件とする。
2026-09-25に次の仕様を確定した。

| 項目 | 確定仕様 |
|---|---|
| Digitalのバリアント | `HH:mm`と`HH:mm:ss`。長押しごとに循環 |
| Forestのバリアント | `HH:mm`と`HH:mm:ss`。背景の主題は共通 |
| Forestの電池表示 | 残量30%未満または充電中に表示。30%以上かつ非充電では非表示。ヒステリシスなし |
| 文字盤の保存 | 選択した文字盤の種類を安定IDで永続化し、再起動後に復元する |
| 文字盤固有状態の保存 | バリアント等の保存有無・内容は各WatchFaceが決められる。ホストが専用の永続化APIを提供する（5.3節） |
| 一時停止中の情報 | ストップウォッチのPaused / Resetでは表示しない |
| ストップウォッチの書式 | 1時間未満は`mm:ss`、1時間以上は`HH:mm` |
| 実行情報の件数 | Digital・Forestとも登録順で最大2件 |
| 書体（2026-09-26） | 時刻はDigitalがD-DIN-PRO Exp SemiBold 100px、ForestがD-DIN-PRO Condensed SemiBold 120px。秒表示バリアントも同サイズ（見た目により見直す）。通常の文字はExp Bold 28px、小さな文字は同22pxで両文字盤共用。詳細は[フォント記録](fonts.md) |
| 時刻の収録文字 | 数字・コロン・ハイフン |
| 時刻の桁揃え（2026-09-26） | 数字はプロポーショナルのまま詰める。`HH:mm`はHHを右揃え・mmを左揃え、`HH:mm:ss`はHHを右揃え・mmを中央揃え・ssを左揃え。コロンの位置はバリアントごとに固定。両文字盤に適用 |
| 充電状態の反映（2026-09-26） | 電池は30秒周期に加え、1秒周期で取得しているUSB給電状態が変化したときにも読み直す。反映は約1秒 |

以下は実装を具体化するための暫定案であり、実機調整や実装前の見た目確認で変更できる。

| 項目 | 暫定案 |
|---|---|
| 長押し | 移動しないタッチを600ms保持し、1押下につき1回発火（2026-09-26、実機で確認し採用） |
| 文字盤選択 | 設定トップに「文字盤」を追加し、Digital／Forestを選択する最小画面 |
| Digital・Forest固有の保存方針 | 両方とも選択したバリアントを保存する実装案。共通契約として全WatchFaceに保存を強制しない |
| 一覧遷移 | Digitalは従来同様の上移動を自身で適用。Forestは静止して一覧に覆われる |
| 一覧背景色 | 両文字盤とも初期値は黒。契約として文字盤が提供し、別の色も診断で検証する |

文字盤選択とバリアント切替は別の操作とし、長押しで文字盤自体は切り替えない。
バリアントは文字盤ごとに保持し、選択の往復で失われないよう、キャッシュのbegin/endと設定値の寿命を分ける。

### 3.2 Digital

- 参考画像の数字の形・太さ・余白を基準に、時刻だけでなく日付・電池・情報欄の文字品質も揃える。
- 通常は時分を分境界で更新し、秒表示バリアントは秒境界で更新する。
- 情報がある場合は時刻と情報欄の配置を変え、APPSを含めて円形画面内に収める。
- バッテリーは常時表示する。取得失敗は0%と扱わず、不明表示にする。

### 3.3 Forest

- 空・地面・木の構成と色、時刻、情報表示時に風景の位置が変わる構成を参考画像に合わせる。
- 木の斜辺、文字、電池・アプリアイコンはアンチエイリアス付きとする。
- 電池またはバックグラウンド情報が表示されるとき、情報欄を確保して風景を配置し直す。
- 電池表示と実行情報は独立して出現・消失できる。非充電では29%で表示、30%で非表示。充電中は残量にかかわらず表示する。
  電池取得失敗で低残量と誤認しない。残量不明かつ充電中では不明表示、非充電で初回不明時は非表示、
  表示中の残量取得失敗では不明表示を暫定方針とする。充電状態自体の取得失敗時の扱いも実装時に定義する。
- APPSを描かないため、Digital用の見えないタップ領域を残さない。一覧はA/Bまたは上スワイプで開く。

フォントは利用・再配布条件を確認できるものを選び、元ファイル・ライセンス・生成手順・サイズ・収録文字を記録する。
既存の`tools/build_font.py`とVLW描画を確認し、再利用できる部分を使う。大きな数字を低解像度から拡大する方式は避ける。
秒表示の桁数、無効時刻、100%の電池、長いラベルが円形端から切れないことを確認する。

## 4. バックグラウンド情報の契約

### 4.1 アプリが識別情報と文字列を提供する

アプリ側の供給元が、計測サービス等を参照して表示用の情報を作る。
供給元は画面の入退場と独立した寿命を持たせ、`HostApplication`でサービスとともに構成・登録する。
WatchFaceがStopwatchServiceを直接参照したり、生の経過時間から文字列を組み立てたりしない。

契約の概念形（名前・容量は実装時に確定）:

```cpp
struct BackgroundInfo {
    AppId appId;       // 安定ID。「何のアプリか」
    FixedLabel label;  // アプリが整形した表示希望文字列
    const IconBitmap* icon;       // 任意の単色濃淡マスク。静的な不変資産
    OptionalColor suggestedColor; // 任意の推奨色。採用するかは文字盤が決める
};
// 供給元は現在の0件または1件の情報と、次に文字列が変わる単調時刻を返す。
// ホストは登録済み供給元から固定容量の一覧を作り、同一フレーム中は不変にする。
```

- アプリ側のFeatureに置く情報供給元が、アイコンと任意の推奨色も提供する。StopwatchServiceは計測だけを担当し、描画資産に依存しない。
- WatchFaceは渡されたアイコン・文字列を使って表示を構成し、サイズ・色・配置・装飾を決める。Digitalは推奨色をチップに利用し、Forestは推奨色を無視して白で描ける。
- 未知のアプリIDでも提供されたアイコンを使える。アイコン未指定・不正な寸法の場合は汎用アイコンへ退避し、推奨色未指定の場合は文字盤の既定色を使う。
- ラベルを数値として解析・再整形しない。アプリが`mm:ss`を希望した場合に文字盤が`HH:mm`へ変換しない。
- 表示位置・装飾・表示する件数・表示しない判断はWatchFace側に残す。
- 共通の`ui/`はAppIdを解釈せず、マスク・色・座標を受けて描く。ホーム側にアプリIDからアイコンへの対応表を設けず、LaunchRegistryも参照しない。
- アイコンは8bitの単色濃淡マスクとし、記述子と画素データはアプリ実行中有効な静的・不変資産を参照する。スナップショットでは参照だけをコピーする。既存資産は複製せず共有可能な場所へ分離して再利用する。
- ラベルは集約時に所有する固定容量バッファへコピーし、フレーム終了前に無効になるポインターを渡さない。
  上限長・UTF-8境界での切り詰め・空文字列の扱いを定義し、画面上の省略と供給バッファ上限を分ける。
- 固定件数上限と登録順による安定した順序を定める。容量超過を診断し、メモリ破壊や毎フレームの確保を起こさない。
  今回の2文字盤は登録順で最大2件を表示し、それ以上の情報は表示しない。

### 4.2 ストップウォッチの供給元

`features/stopwatch/`に画面から独立した情報供給元を置き、StopwatchServiceのスナップショットを使う。
表示書式は次のとおり（2026-09-25確定）。

| 状態・経過時間 | 供給する内容 |
|---|---|
| Running、1時間未満 | AppIdと`mm:ss`。秒未満は切り捨て |
| Running、1時間以上 | AppIdと`HH:mm`。分未満は切り捨て |
| Paused / Reset | 情報なし |

`59:59`から`01:00`への切替、時の桁数増加、表示上限の方針をアプリ側で定義する。
`59:59`から`01:00`で表示単位が変わる仕様とし、単位付き文字列への変更は行わない。整形はアプリ側に置く。
停止・再開・リセット時は状態変更を通知し、ホームへ戻った最初のフレームでも最新状態を使う。
計測値そのものを表示上限で切り詰めない。日時変更で経過時間や更新期限が飛ばないよう単調時刻を使う。

### 4.3 更新期限と通知

- 供給元が、次にラベルが変わる絶対期限を返す。ストップウォッチは計測開始・再開に基づく秒／分境界であり、壁時計の秒境界とは区別する。
- 時計の分／秒境界、電池取得期限、表示中の情報の更新期限、遷移期限の最小値で描画する。
- 文字列が変わらない間は25ms周期のストップウォッチ画面更新をホームへ引き継がない。
- 情報を表示しない文字盤、一覧やアプリで完全に覆われたホーム、消灯中では、情報ラベルの更新のためだけに起床・描画しない。
  状態変更は保持し、再表示時に最新値を生成する。将来のタイマー満了など、表示と独立した業務期限はこの抑止の対象外。
- 情報の追加・削除・ラベル変更を区別できる変更通知をUIタスクで配送する。
  不要な常駐タスクや毎秒の全供給元ポーリングは追加しない。

## 5. WatchFace APIと入力配送

既存の`begin / end / plan / paint / nextUpdate`を拡張する。設定画面等の全体モデルは渡さない。

| 契約 | 内容 |
|---|---|
| データ | 日時・有効性・電池・充電状態・バックグラウンド情報。1フレーム中は不変 |
| 表示環境 | 画面サイズ、一覧進捗0〜1、被覆されていないクリップ、可視状態 |
| イベント | 日時変更、電池・実行情報の変更、進捗変更、タップ（座標付き）、長押し、復帰・選択 |
| 文字盤の出力 | 一覧背景色、次回更新期限、再描画要求、一覧を開く等の意味要求 |

イベント処理は表示状態を更新し、描画はplan/paint経由で行う。イベントからHAL・RTC・NVSを直接呼ばない。
変更フラグと不変スナップショットの組み合わせを基本とし、任意の購読者を持つ汎用イベントバスは導入しない。
バリアント変更時は表示期限も取り直し、秒表示を終了した後に秒周期だけが残らないようにする。

### 5.1 タップとシステム操作の境界

- タップのヒットテストと意味付けはWatchFace側が所有する。システムはAPPSの固定領域を持たない。
- Digitalは自分が描いたAPPSの領域でタップを受けたときに`OpenAppList`要求を返す。Forestはタップを無視してよい。
- WatchFaceはScreenManagerを直接操作せず、イベント処理結果として要求を返す。ホストが要求を受理し、既存の一覧遷移を開始する。
- システムはジェスチャーを認識し、ホームが操作可能で一覧遷移中でないときだけタップを文字盤へ配送する。座標は文字盤の表示領域に対応するローカル座標として契約を統一する。
- 上スワイプ・一覧からの戻り・A/Bによる一覧表示・A+Bホームはシステム側が所有する。文字盤がタップ未実装でも一覧へ到達できる。
- タップは解放時に確定する。スワイプ、長押し、復帰に消費した押下をタップとして配送しない。
- 作業10で扱う画面操作要求は`OpenAppList`に限定する。情報ラベルのタップから対応アプリを開く機能は今回追加しない。

### 5.2 長押し

長押しはInputControllerが意味イベントに変換し、ScreenManager／LauncherControllerがホームで受け付けるかを決め、HomeLayerから選択中の文字盤へ配送する。

- ドラッグしきい値を超えた押下は長押し候補から除外する。
- 長押し成立後は解放までタップ・ドラッグに変換しない。APPS上の長押しでも解放時に一覧を開かない。
- 一覧遷移中・一覧上・他画面・消灯復帰用タッチでは文字盤の長押しを発火しない。
- A+Bホームを優先する。ホーム・画面切替・物理ボタンによる一覧開始時は候補をキャンセルする。
- 保持中は既存の入力追従を利用し、指が静止して割り込みが増えなくても期限に到達する。
- 長押ししきい値とA+Bの保持判定は別の状態として扱う。

### 5.3 文字盤の永続化

文字盤の選択と文字盤固有の状態を分ける。

- 選択IDはホストが保存する。配列位置ではなく`digital`・`forest`等の安定IDを使い、選択先の初期化成功後に保存する。
  未保存・未知ID・読取失敗時はDigitalへ退避する。保存失敗は通知し、現在の表示は利用可能なまま維持する。
- バリアント等はWatchFaceが保存の有無・内容・形式の版を決める。ホストはバリアントの意味を解釈しない。
  Digital・Forestでバリアントを保存する方針は実装案であり、すべての文字盤への義務ではない。
- ホストは文字盤IDで分離した読み書きAPIを注入する。文字盤に任意のNVS名前空間・他文字盤の設定を操作させず、
  保存サイズに上限を設ける。NVSへの直接アクセスはストレージ実装に限定する。
- WatchFaceは状態変更を確定するイベントから保存を要求できる。plan/paintや毎秒更新から書き込まない。
  同値の再保存を避け、読み書きの成否を呼出側へ返す。未保存・不正値・未知の形式は各文字盤の既定値へ退避する。
- 永続化を使わない文字盤もホーム往復・消灯・選択往復の間はRAM状態を保持できるようにし、キャッシュ解放と分離する。
- 既存の輝度・消灯時間設定を保持する。現行の版付き設定レコードを拡張する場合は旧版からの移行を実装する。
  文字盤固有状態は別レコードとし、新しい文字盤の追加だけで共通設定のスキーマ改訂を必要としない構成にする。
  読取・保存失敗や未知版を理由にNVS全体を消去しない。

## 6. 背景復元と一覧の重ね描き

### 6.1 描画の契約

単一UIタスク、全レイヤー共通のFramePlan、1フレームでの転送を維持する。
更新領域内の背景を復元した後、その領域に重なる前景を背面から描き直す。
Forestの背景を通常の全面Elementとして追加するだけで済ませない。現在の重なり伝播では、情報欄の秒更新まで全面再描画へ広がるため。

実装では背景復元の処理を通常要素の変更伝播から分け、必要な領域にクリップして描く方式を第一候補とする。
既存レイヤーの黒背景消去は既定動作として維持し、変更した描画契約に順次適合させる。
背景の構成や位置が変わる場合はその影響領域も更新対象とし、文字の変更だけなら風景全体を転送しないことを検証する。

- 文字・アイコンの縁は復元した実背景に対して合成する。黒を焼き込んだキャッシュを色付き背景へそのまま置かない。
- AAの縁も旧・新矩形に含め、繰り返し描画による縁の濃化や黒い残像を防ぐ。
- 背景の上にある複数要素、トーストの表示・消失、StatsOverlayの領域復元も扱う。
- 消える要素の旧領域、文字盤・バリアント切替、消灯復帰、容量超過の全面再描画を維持する。
- Forestの背景は図形や必要な部分資産から再描画する。通常版に全画面の中間RGB565バッファを追加しない。
- キャッシュ確保は初期化・構成変更時に限定し、失敗時は直接描画へ退避する。時計が表示不能にならないようにする。

### 6.2 一覧

描画順を`WatchFace → 一覧の不透明な背景 → 一覧の行 → 他の画面 → 通知`とする。
一覧の背景は進捗に応じて下から表示領域を広げ、行間からForestが透けないようにする。
背景と行は同じ進捗・表示領域を使う。文字色、文字キャッシュの背景、アイコンの縁も一覧背景色に対応させる。

FrameComposerはWatchFaceの位置を一律に上へ動かさず、被覆範囲と可視性を決める。
Digital側が進捗から移動量を計算し、Forestは移動しない。進捗の生成とボタン／スワイプの補間はLauncherControllerが引き続き所有する。
完全に覆われた時計の更新停止と、戻り始めた際の最新データでの再描画をRuntime・描画構成で共通の判断にする。
