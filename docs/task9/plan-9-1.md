# 作業9-1: 共通型とモデルの分割計画

作成日: 2026-09-23。状態: 実装済み・ホスト検証済み。実機確認は9-5で実施。
対象は[作業9の計画](plan.md)の9-1。比較基準は[9-0の記録](baseline.md)。

## 1. 到達点と範囲

表示に必要なデータ、配置に必要な情報、実行時に適用する設定を分離する。
各画面の入力判定・各レイヤー・文字盤が、他機能を含む `ScreenModel` に依存せず動作する状態を作る。
9-1では見た目、操作、更新周期、保存形式を変更しない。

今回実施すること:

- `TimeUs` を入力から独立させる。
- 表示サイズと描画条件を共通型にし、配置関数とヒットテストで共有する。
- 機能別モデルを分離し、利用側の引数とincludeを変更する。
- 輝度・消灯時間を描画モデルから取り除き、実効設定としてRuntimeへ渡す。
- 統計表示の有効状態をアプリ全体の実行時設定として扱う。
- ストップウォッチの計測用型と、表示モデル・書式・表示更新周期を分離する。

9-2以降へ残すこと:

- ListView/ListController、可変件数・安定行ID、キャッシュ、トースト部品の抽出（9-2）。
- 設定トップの配置・スクロール変更（9-3）。
- LauncherController、サービスや文字盤の所有権変更、Rendererから描画構成の完全分離、既存実装ファイルの一括移動（9-4）。
- 共通化による性能改善の評価と最終的な全体ドキュメント更新（9-5）。

## 2. 現状から導く変更点

| 現状 | 9-1での対応 |
|---|---|
| `input/InputController.h` に `TimeUs` が定義されている | `core/Time.h` へ移し、時間だけが必要な箇所の入力依存を除く |
| `ui/DisplayModel.h` に画面ID、機能別モデル、時計データ、描画I/F、電源設定が集まる | データとI/Fを責務別に分け、包括includeへの依存を解消する |
| Layout関数が `ScreenModel` を受け取る | サイズ・機能別モデル・必要な描画条件だけを渡す |
| 3つのAppScreenに `layoutModel()` がある | 全体モデルの再構築を廃止し、描画と同じ配置関数を直接呼ぶ |
| DigitalWatchFaceが `ScreenModel` をコピーする | 時計データと表示領域・オフセット・クリップのみ受け取る |
| Runtimeが描画モデルから輝度と消灯時間を取得する | `effectiveSettings()` 相当の別経路を作る |
| `SettingsScreen::stats_` が全体の統計表示状態を所有する | アプリ側で所有し、設定画面から変更できるようにする |
| `services/Stopwatch.h` が計測状態・表示モデル・書式・周期をまとめる | サービスに必要な型と容量を残し、表示側の定義を機能フォルダへ移す |

## 3. 型と依存の方針

以下の名前は案。責務と依存方向を固定し、既存コードに合わせて命名は調整する。

| 配置案 | 内容 |
|---|---|
| `core/Time.h` | `TimeUs`。符号付き64bit・マイクロ秒、期限なしの `INT64_MAX` という既存の意味を維持 |
| `ui/Viewport.h` | 表示サイズ、表示可否、オフセット、クリップ。既存の `Rect` を利用 |
| `ui/Scale.h` | サイズだけに依存する `scaled` / `offsetPx`。ListLayoutを他機能が倍率計算のためだけにincludeしない |
| `features/home/HomeModel.h` | `WatchData` とホーム固有の表示情報。`nextMinute` も時計側へ分離 |
| `features/launcher/AppListModel.h` | 選択、スクロール、名前、薄い表示など現在の一覧データ。5件という現行仕様は9-2まで維持 |
| `features/settings/SettingsModel.h` | `SettingsView`、編集値、カーソル、情報表示用データ |
| `features/external/ExternalModel.h` | `ExternalPhase`、スロット詳細、起動エラー等 |
| `features/stopwatch/StopwatchModel.h` と表示用ヘルパー | 表示サンプル、上限、書式、表示更新周期 |
| `app/EffectiveSettings.h` | 実効輝度と保存済み消灯時間。描画I/Fへ渡さない |
| `app/RuntimeSettings.h` | 起動時false・非永続の統計表示有効フラグ |
| `app/FrameModel.h` / `app/ScreenId.h` | 構成側が束ねるフレームデータと画面識別 |

表示サイズは倍率計算に使う論理サイズ、オフセットとクリップは描画先の座標として意味を明記する。
全画面の通常表示はオフセット0・画面全体クリップとし、ホーム／一覧遷移では現行の整数丸めと計算順を維持する。
入力座標と描画座標の変換は一度だけ行い、矩形の右端・下端を含まない現在の判定を変えない。

機能別モデルは他機能のモデルや全体モデルをincludeしない。モデルは固定容量の値型を基本とする。
既存の借用文字列は少なくともフレーム終了まで有効とし、ローカル変数の文字バッファへの参照を返さない。
`ExternalModel` の既存の `SlotStatus` 利用は維持してよい。9-1で状態の二重定義や汎用化を追加しない。

`DisplayDataSource` は時計データ供給の境界、`RenderPort` はRuntimeと描画実装の境界として別ヘッダーへ分ける。
全体データから各機能への変換と、遷移からオフセット・クリップへの変換は `app/` に限定する。

移行中はRendererの入口が構成側のフレームデータを受け取る形を許容するが、各Layer・WatchFace・Layoutへは渡さない。
Renderer内の一覧・トースト関数も必要なデータだけを受け取る。
順序付き描画対象だけをRendererに渡す最終I/Fと、機能レイヤーの所有権移動は9-4で完成させる。
診断用の合成フレーム作成はテスト入力として扱い、製品コードの互換変換を診断側へ複製しない。

## 4. 実装手順

各段階でホストテストと製品ビルドが通る単位に分ける。大規模なファイル移動は行わない。

### 9-1a: 時間と計測用型の独立

1. `core/Time.h` を追加し、InputController・サービス・HAL・電源・描画から適切に直接includeする。
2. StopwatchServiceが必要とする状態とラップ保持容量を表示側から独立させる。保持件数や計測ロジックは変更しない。
3. StopwatchModel、表示上限・周期、`formatStopwatch` の宣言と実装をストップウォッチ機能側へ移す。
4. CMakeと `tools/test_runtime.py` のコンパイル対象を更新する。

### 9-1b: 機能別モデルと配置引数の分離

1. モデル定義と画面IDを分割し、各画面のincludeを必要な型だけにする。
2. サイズと倍率計算を分離し、Layout関数をサイズ＋必要な機能情報で呼べるようにする。
3. ListLayoutにはスクロール・遷移の描画条件を明示的に渡す。配置式や5件固定の動作は維持する。
4. Settings/External/Stopwatchの `layoutModel()` を削除し、同じ配置関数を描画と入力から利用する。
5. 設定メニューが一覧配置を借りる箇所は、配置引数だけを組み立てる。全体モデルを作り直さない。

### 9-1c: Layer・WatchFace・フレーム境界の移行

1. `app/` で機能モデルと描画条件を束ね、同一フレーム内で不変のデータとして扱う。
2. SettingsLayer / ExternalLayer / StopwatchLayerとWatchFaceの引数・保持データを絞る。
3. レイヤーの表示可否は構成側で決める。非表示化時も空矩形の登録等で旧領域を処理し、履歴更新を飛ばさない。
4. Rendererの一覧・トースト処理、RenderPort、Fake Renderer、RenderDiagnosticsのテスト文字盤を追従させる。
5. 全plan→resolve→全消去→背面からpaintの順序、画面／トースト切替時の全面描画、容量超過の退避を維持する。

WatchFaceの登録・選択・キャッシュの所有者はまだ変更しない。
時計の更新期限、キャッシュ無効化、確保失敗時の直接描画も維持する。

### 9-1d: 実効設定と統計表示の分離

1. 保存済み設定はSettingsStoreを正とし、輝度編集を開いている間だけプレビュー値を使う。
2. ScreenManager等の構成側に `effectiveSettings()` を用意し、Runtimeは描画モデルを介さず参照する。
3. HALへの輝度適用、消灯期限の適用、復帰時の再適用は既存のタイミングと単一路線を維持する。
4. RuntimeSettingsをアプリ側で所有する。9-1ではScreenManager所有を基本とし、SettingsScreenへ参照を渡す。
5. 情報画面の「有効化済み」表示には必要なboolだけを渡し、StatsOverlayには有効状態だけを渡す。描画側へ実行時設定の変更権限を与えない。
6. 描画モデルの輝度・消灯時間フィールドと旧包括ヘッダーを削除する。移行用の互換I/Fは残存箇所と削除工程を明示する。

## 5. 検証

### ホスト

`python tools/test_runtime.py` の既存6スイートを継続する。単なる型のコピーを確認するテストは増やさず、境界変更で壊れやすい以下を補強する。

- 既存の座標期待値を維持し、描画矩形とヒットテストの一致、遷移端点・中間・非表示を確認する。
- 輝度のプレビュー、保存、キャンセル、ホームによる破棄、保存失敗、消灯からの復帰で実効値とHAL適用を確認する。
- 消灯時間は保存時のみ変化し、未保存の編集値をPowerManagerへ適用しない。
- 統計表示は情報画面から有効化され、退場後も持続し、新しいアプリインスタンスではfalseに戻る。NVSには保存しない。
- ストップウォッチの表示上限・40Hz期限・書式と、画面退場後の計測継続を維持する。
- 外部起動確定前のホーム中断、起動中描画後のAPI呼び出し、確定時だけの計測停止を維持する。
- GPIO待機、早期起床、消灯中の描画停止等の既存Runtimeテストを通す。

includeの確認で、TimeUs取得だけのInputController依存、機能側の全体モデル依存、全体モデルを再構築する `layoutModel()` が残っていないことを調べる。

### ビルド・実機

- 製品、測定、描画検証の3構成をビルドし、`tools/verify_build.py` で検査する。診断コードの追従漏れも対象とする。
- 実機が必要な以下の確認は、ユーザー指定により9-5へまとめる。9-1のホスト完了と実機確認済みを混同しない。
  - 描画検証版で既存234件の差分／全面描画比較を再実行する。比較件数が変わる場合は理由を記録する。
  - 9-0の記録と照らしてホーム・一覧・設定編集・外部詳細・ストップウォッチ・遷移を目視確認する。
  - 輝度編集からのキャンセル／ホーム、保存後の消灯・復帰、統計表示、静止時の描画停止を確認する。
  - CPU/DFS・USB・診断条件を9-0に揃え、一覧操作と静止区間の描画時間・RAM/PSRAMを比較する。30fps超の達成は9-1のホスト完了条件に加えない。
  - 書き込み時は既存のMultiFirm手順・保護を守り、終了後は通常版へ戻す。

ログは `docs/task9/` に日付・9-1・構成・内容を含む新しい名前で保存し、既存ログを上書きしない。
標準出力・標準エラーを直接ファイルへ保存し、終了コードと `rg` で抽出した必要な結果だけを取得する。
