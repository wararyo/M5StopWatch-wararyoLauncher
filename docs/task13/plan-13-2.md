# 作業13-2: PedometerService・保存・ホストの接続

作成日: 2026-10-07。上位計画は[作業13の計画](plan.md)の1.1〜1.2節、2.2〜2.5節。

## 構成

| 場所 | 役割 |
|---|---|
| `services/PedometerService.*` | 日の番号の計算（純関数）、今日の歩数、区切り、`ClockFollower`。IMUの読み取りはHALを借りて行い、日時の有効性は`TimeService`を借りて見る。保存は知らない |
| `storage/PedometerRecord.*` | キー`pedometer`の記録。`[0]`版1、`[1..4]`日の番号（int32）、`[5..8]`歩数（uint32）。最後に保存できた値と違うときだけ書く |
| `host/HostRoutine.h` | ホストへ登録する口。毎step呼ばれて期限を返し（消灯中も待つ）、消灯したときと、時計を描くフレームで情報を集める前にも呼ばれる |
| `features/pedometer/PedometerRoutine.*` | サービスと記録をつなぐ。起動時の引き継ぎ、消灯時と外部起動確定時の保存、時計の描画に相乗りした30秒ごとの読み取り |
| `host/HostRuntime.*` | `bindRoutine()`。`begin()`、毎step、消灯時、時計の描画前に呼び、期限を`wait()`に入れる |
| `host/HostApplication.h` | 所有と接続。`HostShutdown`から保存を呼ぶ |
| `storage/WatchPreferences.cpp` | `pedometer`を予約キーにする |

## 日の番号と期限

- 日の番号 = `dayFromUnix(UTC秒 + 9時間 − 4時間)`。その日の始まりのUTC秒 = `日の番号×86400 − 9時間 + 4時間`。
- 区切りの期限は、次の日の始まりのUTC秒を、今のシステム時計との差で単調時刻に直したもの。毎step求め直すので、時計の合わせ直しや手動設定に追従する。
- 合わせ直しは区切りの10分前と1分前（`pedometerAlignmentLeft()`）。タイマーと同じく、予定の点で始まった合わせ直しは予定の点から次を決める。
- 区切りの時刻に読めなければ1秒後に読み直し、3回失敗したら最後に読んだ値で区切る。

## 今日の歩数

- 今日 = 引き継ぎ +（最後に読んだカウンタ − 今日の始まりのカウンタ）。起動時のカウンタは0から始まるので、どちらも0から始める。
- 読んだカウンタが前回より小さければ、それまでの分を引き継ぎへ移し、始まりを0にする。
- 時刻が未設定の間は日を持たない。有効になったら、その時の日を今日にし、歩数は保つ。
