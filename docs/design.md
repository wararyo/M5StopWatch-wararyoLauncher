# wararyoLauncher 設計メモ

## 初期スコープ

初期版は時計をホーム画面とし、時計、アプリ一覧、ストップウォッチ、設定、外部アプリ1を実装対象とする。今回の試作は時計、一覧、画面OFF／復帰までとする。

外部アプリへ切り替えた時点でストップウォッチは停止し、タイマー・アラームは通知しない。外部アプリから戻った場合は時計を表示する。将来の経過時間復元、外部アプリ中の通知、RTC・タイムゾーン共有は、M5StopWatch-MultiFirm側の共有APIを利用して追加する。

## 責務の境界

| モジュール | 責務 |
|---|---|
| `LauncherApp` | 画面、選択項目、スクロール位置などのUI状態。ハードウェアへ直接アクセスしない |
| `WatchFace` | 渡された時刻・電池情報の描画と更新間隔。入力・RTC・電源を操作しない |
| `InputController` | タッチジェスチャ、A/B短押し、A+B 0.6秒保持を意味のあるイベントへ変換 |
| `PowerManager` | 無操作時間、パネルOFF、復帰。将来はCPUクロックとlight sleepも管理 |
| `TimeService` | RTCからシステム時刻を初期化し、JSTの表示時刻を提供 |
| `Renderer` | M5GFXによる画面合成。アプリ状態を変更しない |
| MultiFirm連携（未実装） | スロット列挙、検証、外部アプリ起動。UIからイメージ検証処理を分離 |

## 入力規約

- A短押しは「次へ」、B短押しは「決定」とする。
- A+Bを同時に0.6秒保持すると、どの内蔵画面からでも時計へ戻る。
- 同時押しをAまたはBの短押しとしても処理しない。
- 画面OFF中の最初のタッチは復帰だけに使い、アプリへ渡さない。物理ボタンは復帰後も通常の入力として扱う。
- 時計画面で上方向へ50 px以上スワイプすると一覧へ移る。

## 描画と性能

操作中の目標は30 fps以上、静止中はイベント駆動の再描画とする。時計は分境界、電池表示は30秒間隔で更新する。試作では466角相当のRGB565全画面スプライトをPSRAMに確保し、各描画時間をシリアルへ出す。33.3 ms以内を合格とする。

全画面転送が目標を満たさない場合は、次の順で見直す。

1. 一覧の可視領域と時計の変化領域だけを更新する。
2. フォントラスタライズ済みの部品をキャッシュする。
3. 転送待ちとアプリ処理を分離する。

## 電源状態

最終設計では以下の状態を持つ。試作は240 MHz固定で、`Active`、`UsbActive`、パネルだけを停止する`ScreenOff`を実装する。PMとlight sleepは測定用の基準値を得た後に追加する。

| 状態 | 表示 | CPU・待機 | 用途 |
|---|---|---|---|
| Active | ON | 描画性能優先 | 操作・アニメーション中 |
| WatchIdle | ON | 再描画抑制、将来PM適用 | 時計を見ている間 |
| ScreenOff | OFF | 将来light sleep適用 | 無操作時 |
| UsbActive | 状況による | USBコンソール維持 | 書き込み・測定・診断 |

電力測定は最小機能が安定した後、時計静止、一覧操作、画面OFFを分けて行う。USB接続時の電流と、light sleepが有効な電池駆動時間は別の評価とする。

## 試作の実機確認

1. 起動後にRTC時刻がJSTで表示される。RTCが無効なら `SET TIME` と `--:--` を表示する。
2. 時計の上スワイプが一覧へ追従し、シリアルの全フレームが原則 `budget=PASS` になる。
3. Aで選択が循環し、Bで現在の仮アクションを表示する。
4. 一覧でA+Bを0.6秒保持すると時計へ戻り、短押しイベントが混入しない。
5. 30秒後にパネルがOFFになり、最初のタッチでは画面だけが復帰する。
6. 時計静止中に継続的な再描画が発生しない。
