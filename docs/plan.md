# wararyoLauncher 設計書

更新日: 2026-09-20。旧設計メモを本書へ統合する。

本書は製品版の実装方針であり、実装済み機能の一覧ではない。測定用試作は `measurement/`、測定事実と再現手順は [measurements.md](measurements.md) を参照する。合意した要件と、実機調整できる既定値を区別して記述する。

## 1. 目的と初版の範囲

M5StopWatch-MultiFirm の `ota_0` で動作する、軽量・省電力なホストを作る。時計をホームにし、全画面を素のM5GFXで描画する。LVGLは使用しない。Wi-Fi・BLEを初期化せず、無線経由の設定・更新は実装しない。

| 機能 | 初版 |
|---|---|
| ホーム | デジタル時計1種類。WatchFace追加が可能な構造 |
| アプリ一覧 | 時計から上スワイプで表示。物理ボタンでも操作可能 |
| ストップウォッチ | 開始・停止・再開・リセット。ラップ記録なし |
| 設定 | 日時の手動設定、輝度、消灯時間、バージョン等の情報表示 |
| 外部アプリ | 1〜3を表示し、それぞれ `ota_1`〜`ota_3` を起動。アイコンは数字の埋め込み画像 |
| 共通入力 | Aが次へ、Bが決定、A+Bを連続600ms保持でホーム |
| 時刻 | 表示・手動入力はJST（UTC+9）固定 |
| 電源 | 無操作で画面OFF、入力で復帰。CPUはまず240MHz固定 |
| 技術スタック | PlatformIO + ESP-IDF + M5Unified。描画はM5GFX |

アラーム、タイマー、バッジ、追加WatchFaceは将来機能。未実装アプリのダミー項目は初版に並べない。バッジの画像転送は将来PCから有線で行う。

### 1.1 内蔵画面と外部アプリの境界

| 状況 | 初版 | 将来 |
|---|---|---|
| 内蔵画面間の移動・ホーム・画面OFF | ストップウォッチ計測を継続 | 同左 |
| 外部アプリへ切り替え | ストップウォッチ停止。再起動をまたぐ値の保存・復元なし | MultiFirm APIで経過時間を復元 |
| 外部アプリ中のタイマー・アラーム | 通知しない。初版では機能自体を実装しない | MultiFirm APIとゲストの協力で通知 |
| RTC・タイムゾーン | ホスト内の規約だけを定義。ゲストとの統一は保証しない | MultiFirm共通APIに移行 |
| 外部アプリからの復帰 | 必ず時計画面 | 同左 |
| USB時刻設定 | 実装しない | MultiFirm側のツール/APIを検討 |

外部アプリ起動中にホストは動作しない。共有状態をランチャー独自のNVS形式で先行実装しない。

## 2. 測定結果と採用判断

### 2.1 描画方式

試作の描画対象はM5GFXが提供する468×468のRGB565フレームバッファ。設計画像や公称の466角を固定せず、実装では `M5.Display.width()/height()` から領域を取得する。円形画面端には文字・操作対象の安全領域を設ける。

| シナリオ | 平均描画時間 | 最悪描画時間 |
|---|---:|---:|
| 一覧スクロール | 13.6ms | 25.6ms |
| 時計→一覧 | 12.1ms | 17.3ms |
| 時計の分更新 | 3.8ms | 13.8ms |
| 時計静止 | 描画0回/120回 | — |

採用方針:

1. M5GFX所有のPSRAMフレームバッファへ直接描画する。中間の全画面スプライトは追加しない。
2. 前フレームを保持し、変化した要素と影響を受ける要素だけ再描画する。
3. 画面外要素をカリングし、大きな時刻文字など効果を測定済みの部品をキャッシュする。
4. データキャッシュ64KiB／ライン64Bを基準にし、内部RAMを32KiB多く使う分を予算へ含める。

上記は描画処理時間であり、入力・待機を含む製品版の実fps保証ではない。外部アプリ2・3、日本語、円形に沿う一覧、設定画面等を追加した状態で再測定する。

### 2.2 電力の評価

CPU 240MHz固定、light sleepなし、満充電、充電中でないUSB給電条件での代表値。目視読みの確度は約±2mA。

| 条件 | 結果 | 判断 |
|---|---:|---|
| 時計静止・輝度90 | 38mA | アイドル約40mA目標に沿う基準値。余裕は小さい |
| 画面OFF | 38mA | 当初のUSB側20mA目標は未達。PM導入後に再測定 |
| 最大速度の一覧スクロール | 55mA | 当該負荷条件の値で、装置全体の最大電流ではない |
| 全白30fps | 62mA | 表示内容による増加を確認 |

時計表示と消灯の差は今回の精度では検出できなかった。「画面の消費がゼロ」とは扱わない。消灯は不要な点灯と固定表示の継続を減らすためにも実装する。

描画デューティと電流の線形関係は確認されていない。デューティは描画負荷の指標であり、電流の代用にはしない。

当初の20mA／40mAはUSBテスター側の目標として保持する。電池側のmAは電圧・変換効率・USB動作条件が異なるため、USBの38mAを電池側電流の上限とみなしたり、直接差し引いたりしない。電池駆動の消費電力・稼働時間は別に評価し、目標稼働時間は基準測定後に決める。

測定記録の数値は変更せず保持する。ただし同記録の「表示していても電力を消費していない」「最悪55mA」「38mAは上限値」という解釈は、製品仕様では本節の限定付き評価を採用する。

## 3. ビルドとハードウェア

試作とMuteHidに合わせ、以下を初期基準として版を固定する。

| 項目 | 基準 |
|---|---|
| PlatformIO | `espressif32 @ 6.12.0`、`framework = espidf` |
| IDF | 測定記録は5.5.0。実際に解決された版をビルドログに記録 |
| board設定 | 試作の `m5stack-cores3` を出発点にStopWatch認識・構成を確認 |
| ライブラリ | M5Unified 0.2.16、M5GFX 0.2.28 |
| CPU | 初版240MHz固定。DFS・light sleepは後続段階 |
| メモリ | 16MiB Flash、DIO 80MHz、Octal PSRAM 80MHz |
| キャッシュ | 命令16KiB、データ64KiB、データライン64B |
| RTOS | 試作のCPU1配置・1kHz tickを基準に待機とWDTを検証 |
| MultiFirm | 検証済みコミット/タグに固定、`MULTIFIRM_HOST=1` |

命令キャッシュ32KiBとFlash QIOは試作構成で起動失敗があるため採用しない。全SDK・全ブートローダ共通のハードウェア制約とは断定しない。依存更新時にはMultiFirmの既存ブートローダとの互換性も再確認する。

表示・タッチ・ボタン・RTC・必要な電源管理を初期化する。IMU・マイク・スピーカー・Grove 5V出力は初版では無効にする。

## 4. 責務と所有権

| モジュール | 責務 | 境界 |
|---|---|---|
| AppRuntime | 初期化、イベント配送、期限管理、サービス接続 | 業務状態と描画実装を持たない |
| LauncherApp / ScreenManager | 現在画面、選択、スクロール、遷移、ホーム処理 | HAL・NVS・OTAを直接呼ばない |
| AppRegistry | 安定ID、表示名、アイコン、内蔵/外部の起動先 | 外部スロットを配列位置から推測しない |
| 内蔵アプリ画面 | 操作要求と表示モデル | 計測状態を画面に持たない |
| InputController | タッチ・A/B・同時長押しを意味イベントに変換 | 画面遷移や描画はしない |
| Renderer / FramePlan | レイヤー全体の計画、消去、描画、転送 | アプリ状態・時刻・電源を変更しない |
| WatchFace | 与えられたデータの描画と次回更新期限 | 入力・RTC・NVS・電源にアクセスしない |
| TimeService | RTC検証、システム時刻同期、JST変換、手動設定 | 時刻変更イベントを発行 |
| StopwatchService | 計測・停止・再開・リセット | 壁時計と描画周期に依存しない |
| PowerManager | 消灯期限、復帰、電源ポリシー、将来のPMロック | 画面内容を決めない |
| SettingsStore | ローカル設定の検証・保存・版管理 | 共有NVSを全消去しない |
| MultiFirmAdapter | スロット列挙、起動要求、結果通知 | 検証・OTA処理を複製しない |
| HAL | M5Unified/ESP-IDF経由の周辺機器操作 | 値と成否を上位へ返す |

UI状態とM5GFXは単一UIタスクが所有する。重いスロット検証は専用ワーカーで直列実行し、結果をイベントでUIへ返す。ワーカーは画面やUI状態へ直接触れない。他サービスは原則UIタスクから呼び、不要な常駐タスクを増やさない。共有I2C操作も直列化する。

製品版はルートの `src/` 以下を `app/`, `input/`, `ui/`, `apps/`, `services/`, `power/`, `storage/`, `multifirm/`, `hal/` に分ける。`measurement/` は基準測定用として保持する。

### 4.1 WatchFace契約

試作の `begin / plan / paint / nextUpdateDelayMs` を基礎にする。

- 安定したIDで登録する。初版はデジタル1種類で、文字盤選択UIは作らない。
- 初期化時にキャッシュを確保し、終了時に解放する。フレームごとの動的確保を避ける。
- `plan` はJST時刻、有効性、電池情報、充電状態、表示領域、遷移オフセットを受け、描画要素を登録する。
- 全レイヤーのplan後にRendererが解決・消去し、その後paintする。同一フレームの入力データは不変。
- 次回更新期限をRuntimeが実際に使用する。デジタルは分境界、将来の秒表示は秒境界を指定できる。
- 時刻設定・電池更新・復帰・文字盤切り替えでも無効化する。
- キャッシュ確保失敗時は直接描画に戻し、時刻自体を表示不能にしない。

内蔵アプリ画面は入場・退場、意味イベント処理、表示モデル生成、次回表示更新期限を提供する。ホームは画面へ届く前にScreenManagerが処理する。画面退場は計測停止を意味せず、未保存編集など画面固有の一時状態だけを破棄する。

## 5. 操作と画面

### 5.1 共通の物理入力

A短押しは次の操作対象へ進み、末尾から先頭へ循環する。B短押しは選択中の操作を決定する。短押しはリリース時に確定する。

A+Bは両方が押された時点から600msを数える。一方でも離れたら連続保持時間をリセットする。一度でも同時押しになった押下群は、600ms未満で解除してもA/B短押しへ変換しない。ホーム発火は1回限りで、両方離すまで再発火しない。

タッチ中もホームを優先し、ドラッグ・選択・未保存編集をキャンセルする。時計上のホームは無害な操作とする。対象はホスト内の全画面・ダイアログ・通常の検証待ち。画面OFFなら復帰して時計を表示する。

外部アプリ中の復帰はMultiFirmゲストAPIの責務であり、現行既定は1.6秒。ホストの600ms規約をゲストへ暗黙に適用しない。起動先設定から再起動までの確定処理は取り消せない（8.2節）。

### 5.2 時計・一覧

時計は [WatchFaceDigital.png](WatchFaceDigital.png) を基準に黒背景、電池、日付、時分、APPSを配置する。初期仕様は画像に合わせた英語日付と24時間表示。

上ドラッグに追従して時計が上へ退き、一覧が下から出現する。試作の50px相当を確定しきい値の初期値とし、画面サイズに対する比率で調整可能にする。解放時は短い補間で時計または一覧へ収束する。補間はフレーム数でなく経過時間で進める。時計ではA/B、またはAPPSタップでも一覧を開く。

一覧は [AppList.png](AppList.png) を基準に、ストップウォッチ、設定、外部アプリ1〜3の5項目。円形画面に沿う配置を適用し、試作の固定X座標からの変更を再測定する。

Aで選択を進め、選択項目が見える位置へスクロールする。Bまたは項目タップで開く。ドラッグしきい値を超えたら解放までタップを抑止する。指追従と解放後の位置補正に加え、2026-09-21に解放速度から着地行を決める短距離の慣性スクロールを試験実装した（実機調整は未完了）。一覧先頭での下スワイプは時計へ戻り、それ以外は一覧スクロールを優先する。

空・不正スロットも番号と状態を表示するが起動対象にしない。長い名前は幅に合わせ省略し、詳細画面で確認可能にする。固定の日本語UIに必要なグリフを含め、外部名の未収録文字は代替表示する。任意のUnicode全文字収録は初版の保証外。

一覧の行はアイコンとアプリ名だけで構成し、起動可否の理由文を常設しない。アイコンは直径64px（選択時68px）のアンチエイリアス円と、その上に重ねる44pxのグレースケールマスクで描く。マスクは埋め込み資産で、プリミティブの組み合わせでは描かない。名前はGenShinGothic 28pxのVLWを部分集合化して埋め込み、ASCII・かな・UIが使う約物と固定文言の漢字を収録する。生成手順と退避動作は[作業3の描画基盤](task3/rendering.md)に記す。

### 5.3 ストップウォッチ

状態は `Reset / Running / Paused`。サービスが累積時間と今回の開始時刻を保持し、64bit単調時刻から算出する。日時変更・描画周期から独立させる。

| 状態 | 選択可能な操作 |
|---|---|
| Reset | 開始、戻る |
| Running | 停止、戻る |
| Paused | 再開、リセット、戻る |

Aで選択、Bで実行。開始後は停止、停止後は再開を選択する。タッチでも同じ操作ができ、リセットは停止中だけ有効。ホーム・戻る・消灯では計測を継続する。

表示は `HH:MM:SS.cc`（1/100秒）を既定とし、桁上限では上限表示して内部値は維持する。表示分解能は実機の計測精度保証を意味しない。実行中の可視画面は30Hzを超える表示更新を目指す。他画面・消灯中は表示更新を止め、再表示時に経過時間を算出する。電源断・再起動・外部切り替え後の値の復元は初版では行わない。

### 5.4 設定

輝度90、消灯30秒を調整可能な既定値とする。輝度設定には可視性を保てる下限を設ける。日時は年・月・日・時・分を編集し、保存時に秒を0へ合わせる。

Aでフィールド/候補を送り、Bで編集/確定する。「保存」「キャンセル」を明示し、ホームでは未保存編集を破棄する。輝度のプレビューもキャンセル時に保存値へ戻す。妥当な日付と範囲を保存前に検証する。

## 6. 描画と実行周期

### 6.1 FramePlanの不変条件

1. 全レイヤーの要素の旧矩形・新矩形・内容変更を収集する。
2. 消去と再描画の影響を受ける他要素を特定する。
3. 必要な消去をすべて終える。
4. 背面から前面へ描画する。
5. M5GFXのダーティ領域を転送する。

円は両端を含む `2r+1`、文字は張り出しを含む矩形を使う。消える要素を単に登録から外して消し残さない。画面切り替え・復帰・重なるモーダル/トーストの表示と消去では履歴を破棄した全面再描画を許可する。

初版の基本要素は黒背景を前提とする。背景画像や常時重なりを持つWatchFaceは、背景復元と前景再描画を追加してから対応する。試作の容量12要素を無条件で流用せず、最大要素数を把握し、超過時は診断と全面再描画への退避を行う。

468×468×2bytesは約428KiB。M5GFXのバッファに同等の中間バッファを重ねない。文字キャッシュ、日本語フォント、ワーカーを含め、内部RAM/PSRAMの空き・最大連続領域・スタック余裕を記録する。ピクセル比較用バッファは通常ビルドに含めない。

### 6.2 更新・待機

描画の契機は入力、遷移の次フレーム、表示データの期限、サービス状態変化、復帰。静止中はRendererを毎ループ呼ばず、レイアウト計算も省略する。時計は分境界、電池表示は30秒間隔、時刻設定・復帰は即時更新。画面OFF中は表示期限のために起こさない。

操作中は16ms程度の目標周期から開始する。期限超過時は古いフレームを追いかけず最新状態へ進み、次期限の基準を取り直して最低1tickブロックし、アイドルタスクへ実行機会を渡す。`vTaskDelayUntil` が期限超過で戻り続ける状態を放置しない。WDT無効化・タイムアウト延長を対策にしない。

初版は入力ポーリングを残してよいが、静止中の負荷を測る。PM段階でMuteHidのGPIO通知を参考に、割り込みまたは次期限まで待つ構造へ移す。ISRでは通知だけを行い、I2C・描画を行わない。期限は64bit単調時刻を基本とし、32bitならラップアラウンドを扱う。

### 6.3 性能基準

操作中の継続描画は30fps超を目標とし、描画処理時間と描画完了間隔を別々に測る。規定操作の連続区間で実fpsが30を超え、定常区間のフレーム間隔が33.3ms以内であることを受け入れ基準にする。

平均・p95・最大・33.3ms超過数を記録する。初回描画、復帰、外部起動待ちは別集計。静止中の0fpsは正常で、分更新・電池更新の単発描画を許す。入力→表示は100ms以内、消灯復帰は300ms以内を暫定目標として測定する。暫定値は実機で調整できるが、測らず達成扱いしない。

## 7. 電源・時間管理

### 7.1 電源状態

| 状態 | 用途 | 初版 | PM段階 |
|---|---|---|---|
| Active | 操作・遷移・可視の計測更新 | 240MHz、必要な描画 | 必要な期間だけ性能を確保 |
| WatchIdle | 静止表示。設定等の静止画面も含む | 240MHz、再描画抑制 | DFS/自動light sleepを評価 |
| ScreenOff | パネルsleep、描画なし | 240MHz、待機 | 入力・期限で復帰するlight sleep |
| UsbActive | USB通信・診断維持 | 240MHz、通信維持 | 必要なPMロック |

USBと表示状態は同時に成立するため、内部は表示/操作状態と `usbSessionActive` の2軸とする。UsbActiveは電源ポリシーの上書きで、USB接続だけで常時点灯しない。USB切断時は元の表示状態に対応するポリシーへ戻す。測定モードだけが明示的に消灯を上書きできる。

操作・アニメーションが止まればWatchIdle、最終操作から30秒でScreenOff。ボタン保持・タッチ継続は操作と数えるが、時刻更新・電池更新・計測継続では消灯期限を延ばさない。

消灯時はパネルsleepと描画停止。復帰後は全体無効化し最新状態を描画する。通常復帰は直前の画面、外部からの再起動とホーム操作は時計画面。

最初のタッチは解放までジェスチャ全体を復帰専用として消費する。物理ボタンは復帰後も通常処理するが、A+Bの短押し抑止を先に適用する。

### 7.2 省電力化の順序

240MHz固定で機能・性能の基準を確立した後に、イベント待機、I2Cポーリング削減、DFS、tickless idle、自動light sleepを段階導入する。施策ごとに電力・性能・入力・USB・復帰を比較する。

deep sleepと電源OFFは計測保持・RTC復帰の別設計が必要なので初版対象外。VBUSと実際のUSBデータ接続は区別する。MuteHid同様に保守的なVBUS中sleep禁止を採用する場合、そのlight sleep効果は電池駆動で評価する。

### 7.3 時計

ホスト内部は試作に合わせRTCをUTCとして読み書きし、表示と手動入力だけJSTへ変換する。これはゲストとの共有契約ではなく、他ファームウェアのRTC解釈・変更との整合は保証しない。タイムゾーン設定UIと共有保存は作らない。

起動時にRTC取得結果、日付時刻の範囲、取得可能な有効性情報を確認する。無効なら `--:--` と設定への導線を表示する。システム時計へ同期し、毎描画のRTC読み出しを避ける。

手動保存は検証→UTC変換→RTC書き込み→システム時計更新→表示更新とし、失敗を成功表示しない。途中失敗ならRTCを読み直して整合を回復し、回復できなければ無効状態を明示する。PM導入後はsleepをまたぐ時計・計測の連続性を実機確認する。

## 8. MultiFirm・保存・更新

### 8.1 API

2026-09-20時点の隣接リポジトリには `multifirm_host.h/.cpp` が実装されている。旧メモのAPI未実装を前提にせず、以下を利用する。

- `isMultiFirmLayout()`：レイアウト確認。
- `scanSlots()` / `inspectSlot()`：検証状態、名前、バージョン等の取得。
- `bootSlot(index, shutdown, context)`：再検証、起動先設定、終了処理、再起動。

まず時計を表示し、検証はワーカーで行う。一覧には検証中を表示し、Readyのみ起動可能とする。Empty / Invalid / ReadErrorは区別して表示する。名前の優先順位とメタデータ照合はライブラリに任せる。番号アイコンとスロットは固定対応。

非対応レイアウトでは外部起動を無効にし、内蔵アプリは利用可能にする。検証・起動・復帰時間を診断する。

### 8.2 起動確定とホーム

現行 `bootSlot` は同期・キャンセル非対応で、起動先設定後にvoid型shutdownを呼んで再起動する。単にワーカーへ移すだけではホーム後の遅延再起動を防げないため、次の境界を設ける。

1. 外部アプリ詳細に「起動」「キャンセル」を表示する。計測中なら「計測を終了して起動」と示す。この段階はホーム可能。
2. 最終決定前に失敗し得る設定保存等を完了する。失敗なら起動しない。
3. 最終決定後は `BootCommitting` とし、起動中表示を出してAPIを1回だけ呼ぶ。この区間の取り消しは保証せず、新しい操作を抑止する。
4. API失敗ならエラー表示へ戻し、ホームを再び受け付ける。ストップウォッチは継続する。
5. 成功時shutdownで同期を確保して計測・音・振動等を止める。失敗し得る必須保存をここへ置かない。

通常のスロット走査中のホームは即時に時計へ戻り、後から届く結果はスロット情報だけ更新する。起動自体のキャンセルが必要になったら、MultiFirm側に検証と確定を分けるAPIを検討する。

### 8.3 永続化・書き込み保護

既定 `nvs` 内の専用名前空間 `launcher` に、スキーマ版付きの設定レコードを保存する。複数ホストの共存は想定せず、この名前をホスト用として使用する。輝度・消灯時間は確定時だけ書き、描画・毎秒計測ではFlashへ書かない。

未知の版、不正値、NVS初期化失敗は診断し、必要ならRAM上の既定値で動作する。NVS全体を自動消去しない。専用名前空間でも他ファームウェアの全消去からは保護されないため、MultiFirm側の共有NVS運用にも従う。

ホスト上限は4MiBで、ビルド後とインストール時に確認する。製品版のパーティション表はMultiFirm正規レイアウトに一致させ、試作単体用CSVを流用しない。

更新は `install-host` を使用し、通常のupload/erase/uploadfsによる全体上書きを既定で禁止する。初回導入・ブートローダ変更・復旧はMultiFirmの手順に従う。ホスト破損をrecoverだけで直せるとは扱わない。

`multifirm_meta` は読み取り専用、`multifirm_nvs` は将来API用で初版では使わない。バッジ導入時はstorageの形式と所有ディレクトリを調整し、マウント失敗時の自動フォーマットを禁止する。

## 9. 検証と受け入れ

| 分野 | 必須確認 |
|---|---|
| 入力 | A/B、時間差の同時押し、599/600ms境界、片方解除、再保持、タッチ併用、ホーム1回発火 |
| ホーム | 全内蔵画面、設定編集中、ダイアログ、走査中から時計へ。未保存編集を破棄、計測は継続 |
| 計測 | 開始・停止・再開・リセット、他画面、消灯、日時変更、長時間動作 |
| 時計 | 無効RTC、取得失敗、うるう日・月末・JST日付境界、保存失敗、復帰更新 |
| 描画 | 全面再描画とのピクセル一致。既存24パターンに往復・端位置・5項目・日本語・トースト・復帰・文字盤差し替えを追加 |
| 性能 | 製品画面で6.3節の指標。スクロール・遷移各60秒以上、WDT・描画破綻なし |
| 過負荷 | 意図的な周期超過でもアイドルタスクが走り、追いつきループ・WDT・操作不能なし |
| メモリ | キャッシュ確保失敗時の表示継続、反復遷移でリークなし、要素容量超過の検出 |
| 電源 | 無操作消灯、保持中の非消灯、タッチ消費、ボタン復帰、USB抜き差し、PM後の取りこぼしなし |
| MultiFirm | 各スロット正常・空・破損・読取失敗、非対応表、起動失敗、ゲストから時計へ復帰 |
| データ保護 | ホスト更新でゲスト・設定維持、NVS異常で全消去しない、通常upload保護 |

再描画のピクセル検証は描画変更時に必須。検証機能は通常ビルドでは無効にする。入力・時間・状態遷移はHALから分離してホスト側テストを可能にする。

電力は充電状態、VBUS、表示、輝度、CPU/PM設定、ファームウェア版、測定器精度を記録する。USBと電池は別表とし、電池は点灯時間・操作頻度を固定して稼働時間を比較する。

PMIC低レベル診断は測定済みのI2C 100kHzと成功/失敗を返すAPIを使い、失敗値0を正常値と誤認しない。電圧・残量推定から電流を断定せず、消費電流は外部計測する。

## 10. 残る判断

初版開始を妨げる未決定事項はない。輝度90、消灯30秒、スクロールしきい値、遅延の暫定目標は実機調整可能な設計値とする。スコープ・基本操作を変える場合は再合意する。

MultiFirm共有API、外部中の通知、経過時間復元、USB時刻設定、バッジ転送、電池駆動の目標時間は各導入段階で決める。
