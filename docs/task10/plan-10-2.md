# 10-2: WatchFaceのイベント・入力・更新期限

作成日: 2026-09-25。状態: 実装計画。上位仕様は[作業10](plan.md)、依存は[10-1](plan-10-1.md)。

## 1. 到達点

Digitalがホームのタップと長押しを受け取り、自身でAPPSのヒットテストと時分／時分秒切替を行う。
一覧を開く要求を返し、ホストが遷移を開始する。時計・実行情報の更新期限を必要なときだけ待つ。
描画品質は10-3、実際の一覧被覆と移動責務の変更は10-4、永続化は10-5で接続する。

## 2. 境界とAPI案

`features/home/HomeInteraction.h`をGfx非依存で追加する。

- `HomeEvent`: Tap／LongPressと画面ローカル座標、単調時刻。
- `HomeOutcome`: changed、None／OpenAppList、必要なら通知。
- `HomeControlPort`: イベント配送・選択候補一覧・選択要求を仲介する抽象境界。10-2では入力部分のみ実装。
- `WatchEnvironment`: Viewport、システムによる被覆クリップ、一覧進捗、可視状態。
- `WatchChanges`: 日時設定、電池、情報、進捗、復帰、選択などの変更ビット。

HomeLayerが文字盤状態の所有を続け、HostRendererがHomeControlPortを実装してHomeLayerへ委譲する。
HostApplicationからScreenManagerへこのポートを注入する。ScreenManagerはHostRendererやM5GFXの具象型を参照しない。
PCテストでは偽ポートを使い、画面制御のテストへM5GFXを持ち込まない。

WatchFaceへ追加する契約:

| API案 | 用途 |
|---|---|
| `handle(event)` | UI状態を変更しHomeOutcomeを返す。画面遷移・描画は直接しない |
| `update(data, environment, changes)` | 同一フレームのスナップショットを受ける |
| `backgroundInterest()` | 表示対象IDの固定配列。Digitalは登録順の先頭2件 |
| `theme()` | 一覧背景色。初期値は黒 |
| `nextUpdate(now, data)` | 時計・文字盤固有の更新期限。アプリのラベル期限と分離 |

イベント・スナップショットの受領→状態確定→plan→resolve→paint→期限集計の順とする。
updateは同じデータで複数回呼ばれても状態が進まないようにする。次回期限の問い合わせは副作用を持たない。
時刻が変わっただけで毎回全面invalidateせず、表示文字・要素のfingerprintに反映する。

## 3. 長押しを既存画面へ混入させない

InputControllerへ長押し開始時刻・成立済み・許可ラッチを追加する。
**全画面へ一律に長押し認識を適用しない。** 設定やストップウォッチで長めの押下をTapとして扱う既存操作を維持する。

1. Runtimeが入力を読む際、ScreenManagerから「現在ホームが静止して操作可能か」を取得する。
2. TouchStart時の許可状態をラッチする。途中でホームに戻っても同じ押下で長押しを有効化しない。
3. 600msに達する前にドラッグしきい値を超えたら長押しを取り消す。超えた後に開始位置へ戻っても復活しない。
4. 境界で移動と時間成立が同時ならドラッグを優先する。ホームイベントはさらに優先する。
5. LongPress発火後は解放までTapとDragを抑止し、再発火しない。
6. 一覧開始・ホーム・画面切替は進行中のタッチを消費する。解放後の次の押下から再開する。

既存の保持中10ms追従を使う。静止保持でも判定でき、常時ポーリングへ戻さない。
復帰タッチのconsumeTouchを維持する。A+Bがホームとして成立したサンプルではLongPressを配送しない。

## 4. タップと一覧要求

LauncherControllerからAPPS固定領域の判定を除く。A/B、上スワイプ、一覧側操作はそのまま残す。
ScreenManagerはアクティブ画面・ホーム・ランチャーの順序を整理し、静止ホームのTap／LongPressだけをHomeControlPortへ渡す。
HomeOutcomeのOpenAppListに対してLauncherControllerの公開メソッド`openList(now)`を呼ぶ。
ボタン経由と同じ補間を使い、同じ要求でアニメーションが二重開始しないようにする。

Digitalの配置計算をGfx非依存の`DigitalLayout.h`へ抽出し、APPS描画とhit-testが同じ矩形を参照する。
入力は遷移中には届かないため、座標は静止ホームのviewport原点基準とし、表示領域からの変換をホストで一度だけ行う。
LongPressはAPPS上でもバリアント切替を優先し、解放で一覧を開かない。

## 5. 期限・進捗と段階移行

HostRuntimeは、可視ホームに限り時計期限・電池期限・表示対象情報の期限を合成する。
情報非表示・完全被覆・消灯で表示期限を解除し、復帰では収集し直す。
バリアント変更時はdirtyにして同じターンで期限を再計算する。無効RTCでも実行情報の期限は独立して有効にする。

10-2では進捗を渡すAPIを追加するが、現行DrawRegionのoffsetは維持する。Digitalで進捗からの移動を重ねない。
10-4でFrameComposerの移動を除去すると同時にDigitalへ移動計算を移す。二重移動する中間状態を作らない。
時刻設定・復帰等の通知は既存のdirty経路へ変更理由を添える。電池は既存の30秒取得周期で比較する。
充電表示も取得周期に従う。USB給電の有無を充電中とみなさない。

## 6. 実装順序と検証

1. Gfx非依存の契約と偽ポートを追加する。
2. InputControllerへホーム限定の長押しとキャンセルを追加する。
3. ScreenManager→HomeLayerへの配送とOpenAppList要求を接続する。
4. Digitalの配置共有、時分秒バッファ（終端込み9bytes以上）、分／秒期限を実装する。
5. 10-1の情報と表示対象期限、変更理由の配送を接続する。

`runtime_tests`・`ui_tests`へ以下を追加する。

- 599／600／601ms、1回発火、指の微小移動・しきい値越え・戻り、ホーム同時成立、解放時タップ抑止。
- 他画面での長い押下が従来どおりTapになること、ホームへ途中復帰した押下、一覧開始後の解放、消灯復帰。
- APPS内外、情報あり／なしのAPPS配置、未実装タップ、A/Bと上スワイプの維持。
- 時分→秒→時分で期限が切り替わり、非表示で起床せず、復帰で最新値になること。
- 状態変化と文字列変化、期限だけの変化で不要な再描画が増えないこと。

製品ビルドに加え、実機で保持・誤タップ・秒の変化を確認する。ログと結果は10-2名で保存する。
全体計画への補足候補: 長押しのホーム限定ラッチ、Gfx非依存の入力ポート、10-4まで移動方式を維持する移行順序。
