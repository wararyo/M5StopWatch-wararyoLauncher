# 作業14: ホームジェスチャー

作成日: 2026-10-07。状態: 計画。上位計画は[全体計画](../plan.md)。
見た目の基準は、スワイプ中の帯が[HomeGesture.png](../Images/HomeGesture/HomeGesture.png)、離した後に文字盤が現れる途中が[HomeGesture2.png](../Images/HomeGesture/HomeGesture2.png)。
帯のアイコンは`icons/ic_watchface.png`（文字盤を表すアイコン）。

## 1. 到達点と合意済み仕様

内蔵アプリ画面で、タッチだけでホームへ戻れるようにする。画面の上端から下へスワイプして離すと、文字盤が上から下へ現れてホームに戻る。
A+Bの長押しでホームへ戻るときも、同じ帯と同じ現れ方にする。

### 1.1 帯（ホームジェスチャーUI）

スワイプを始めてから指を離すまで、または A+B を押している間、画面の上端に帯を出す。

- 帯の背景色と、アイコンの色は文字盤が決める。`WatchFace`に`homeGestureBackground()`と`homeGestureForeground()`を足す。
- 帯の高さは最大80px。指が下にあるほど高くなる。指が上の方にあるときは帯の下端が指によく付いてくる。下の方では伸びが鈍くなる。
- 帯の天地中央に`ic_watchface`を置く。帯がアイコンより低いときは、アイコンの上下を帯の範囲で切る。
- `homeGestureBackground()`の既定は黒、`homeGestureForeground()`の既定は白。既存の文字盤は次のとおり。

  | 文字盤 | 背景 | 前景 |
  |---|---|---|
  | Digital | 黒 | 白 |
  | Forest | その時刻の空の色 | 白 |
  | Analog | 黒 | 白 |
  | Noonish | その時刻の上端の色 | 白 |

### 1.2 ホームへ戻る

- 一定の位置より下で指を離すと、ホームへ戻る。判定にはY座標だけを使う。
- 指を離した瞬間に帯は消え、その範囲が文字盤に切り替わる。帯の色を文字盤に合うものにしておけば、切り替わりは目立たない。
- 続けて、文字盤が上から下へ幕のように現れる。quintのイーズアウト（1 − (1 − t)^5）で、600msかけて動かす。
- アニメーション中、アプリ画面は止まったままでよい。境目より下の画面は書き換えない。
- 一定の位置より上で指を離したら、ホームへは戻らない。帯は急なイーズアウト（quint）で、100msかけて縮んで消える。

### 1.3 A+B

- A+B を押している間、600msかけてイーズインアウトで帯を80pxまで広げる。
- 600msでホームが成立したら、指を離したときと同じく、帯を文字盤に切り替えて文字盤を出す。
- A+B の600msと、ホームを画面の処理より優先することは今までどおりである。

## 2. この計画で採用する実装上の初期方針

ここは未指定の部分を補う初期方針である。寸法は466角の画面での値。寸法・時間・曲線は実機で調整してよい。判定や状態遷移を変えた場合は記録する。

### 2.1 スワイプの判定

- 対象は内蔵アプリ画面（設定・外部アプリの詳細・ストップウォッチ・タイマーと、今後足す画面）とする。
  時計と一覧は対象にしない。一覧には「先頭で下へ引くと時計へ戻る」操作がすでにある（`LauncherController`の`Drag::Return`）。
- 上端の帯の範囲は y ≤ 40px とする。そこで始まったタッチは、離すまでシステムのものとし、画面へ渡さない。
  `TouchStart`から画面へ渡さないので、画面が途中から受け取ることはない。この範囲でのタップは何もしない。
- 帯は、ドラッグの始まり（既存の閾値9px）から出す。上端でのタップでは帯が一瞬出ることはない。
- X座標は見ない。斜めでも横でも、帯の高さと成立の判定は指のY座標だけで決める。
- 指を離した位置が y ≥ 120px（帯はおよそ62px）なら成立とし、ホームへ戻る。速さによる判定（はじく操作）は入れない。
- 成立しなかったら、帯を縮める（1.2節）。縮むにつれて帯の下から出てくるアプリ画面は、通常の差分描画で描き直される。
  縮む間も入力は通常どおり受け付ける。縮む途中で上端のスワイプが始まれば、その指の帯に切り替える。
- 注意の要求（タイマーの満了）で画面が前に出たときと、消灯したときは、帯を縮めずにすぐ消す。
- 外部アプリの起動確定中（`exclusive()`）は帯も出さず、成立もしない。今のホームと同じである。
- 消灯からの復帰に使ったタッチは、今どおり離すまで消費する。上端で触って起こしても、そのままホームへは戻らない。
- [docs/plan.md](../plan.md) 5.1節に、次の一般則を足す。特定の画面を例外として名指ししない。
  「内蔵アプリ画面では、上端の帯で始まるタッチはシステムが所有し、下へ動かして離すとホームへ戻る。A+B のホームと同じく例外なく適用する。画面は上端の帯に操作対象を置かない。」
  14-1で、既存の画面の操作対象が上端の帯に入っていないかを確かめる。設定のリストの行はスクロールで帯に入るが、その部分をタップしても何もしないことを許容する。

### 2.2 帯の高さとアイコン

- 指のY座標 y から、帯の高さを h(y) = 80·(1 − e^(−y/80)) で求める。上端では傾きが1で、帯の下端が指に付いてくる。下へ行くほど伸びが鈍る。

  | 指の y | 20 | 40 | 80 | 120 | 160 | 240 | 320 |
  |---|---|---|---|---|---|---|---|
  | 帯の高さ | 18 | 32 | 51 | 62 | 69 | 76 | 79 |

- 帯は画面の幅いっぱいの矩形で、下端は水平。丸い画面の外は見えない。
- アイコンは44×44で、中心を (画面の中央, h/2) に置き、帯の範囲 [0, h) で切る。h が44未満のときは、上下が同じだけ切れる。
- 描き方は一覧のアイコンと同じマスクで、帯の背景の上に前景色で描く。

### 2.3 文字盤の色

`WatchFace`に次の2つを足す。`listBackground()`と同じく、そのフレームの`WatchData`を受け取る。時刻によって変えてもよい。

```cpp
virtual uint16_t homeGestureBackground(const WatchData&) const { return 0x0000; }  // 黒
virtual uint16_t homeGestureForeground(const WatchData&) const { return 0xffff; }  // 白
```

- Digital と Analog は既定のまま使う。黒い画面の上では帯の地は見えず、アイコンだけが見える。
- Forest は、その時刻のパレットの空の上端の色（`skyTop`）を返す。`listBackground()`と同じく、時刻からパレットを求める。
- Noonish は、その時刻に画面の上端の中央が属する領域の色を返す。背景の領域を決めるのと同じ関数で、針と同じ10秒刻みで変わる。
  帯が消えたときに、すぐ下に見える色と同じになる。

### 2.4 A+B の帯

- A+B の帯は、ホームが時計以外のものを閉じるとき（`ScreenManager::screen()`が`Home`以外。アプリ画面と一覧）に出す。時計の上では今どおり何も出さない。
- 帯の高さは 80·easeInOutCubic(経過/600ms)。経過は、両方が押された時刻（入力が600msを数える起点と同じ）から数える。
- 600ms未満でどちらかを離したら、スワイプと同じく帯を100msで縮める。外部起動の確定などで押下が捨てられたときも同じである。
- 入力（`Events`）に、同時押しの始まりの時刻と、同時押しが始まった・終わったサンプルの印を足す。単独押しの`hold`・`holdChanged`と同じ考え方である。
  ホストはこの印でも`ScreenManager::handle()`を呼ぶ。
- スワイプ中に A+B が始まったら、スワイプを取り消し（指を離すまでタッチを捨てる）、A+B の帯に切り替える。

### 2.5 文字盤が現れるアニメーション（幕）

- 成立した時点（指を離したとき、または A+B の600ms）で、A+B のホームと同じ処理をする（`leaveAll()`、ホームの回数を数える）。
  画面はその時点で退場する。鳴っているタイマーはそこで解除され、未保存の編集は捨てられ、輝度のプレビューは保存値に戻る。
  以後アプリ画面は描かれず、画素がパネルのフレームバッファに残るだけになる。「止まって見える」のはこのためで、計測は続いている。
- 境目は、成立時の帯の高さから画面の下端まで、quintのイーズアウトで600msかけて動かす（1.2節）。16ms間隔の期限で進め、補間は経過時間で計算する（一覧の移動と同じ）。
  帯が縮むアニメーションも同じ進め方にする。
- アニメーション中の入力は捨てる。その間に始まった押下とタッチは、離すまで捨てる。ホームへ戻る途中なので、A+B を含めて何もしない。
- 割り込み:
  - 注意の要求（タイマーの満了）が画面を前に出したら、幕を打ち切る。画面の切り替えなので、通常どおり全面再描画になる。
  - 消灯したら幕を打ち切る。復帰時は今どおり全面再描画になる。

### 2.6 描画

**帯の間**は、通常のフレームに帯のLayerを1枚足すだけである。

- `HomeGestureLayer`（`ui/overlays/`、トーストと同じく機能を知らない）を、画面のLayerの後、トーストの前に置く。
- 帯を1つの要素（矩形 [0, h)、fingerprint に色）として登録する。帯の高さが変わると、旧と新の矩形を囲む範囲だけが描き直される。
  その範囲では、まずアプリ画面が描き、その上に帯を描く。下地は今どおり画面の色である。
- アプリ画面はこの間も動いていてよい。`FramePlan`の容量（32）の見積もりに、帯の1要素を足す。

**幕の間**は、フレームを上端から境目までに閉じ込める。

- `Renderer`に、フレームが描ける範囲をフレームごとに狭める口を足す。`FramePlan`の`bounds`をその範囲にする。
  更新範囲はすでに`bounds`で切り詰められ（[Element.cpp](../../src/ui/rendering/Element.cpp) の`resolve()`）、全面再描画も`bounds`だけを覆う。
  今の`limitTo()`と違い、この口は全面再描画を起こさない。
- 合成はホーム（時計、一覧は下に隠れた状態）にする。範囲は {0, 0, 幅, 境目} とする。下地は文字盤の`listBackground()`である。
  - 最初のフレームは、範囲の中を全面再描画する。これで帯が文字盤に切り替わる。文字盤には復帰（`WatchResumed`）を伝える。
  - 画面の切り替えによる画面全体の再描画（`FrameComposer`の`changed`）は、幕の始まりでは行わない。
- 文字盤には、静止時と同じ環境（被覆のないクリップ、一覧の進捗0）を渡す。`HomeLayer`が、前の境目から今の境目までの帯を`damage()`で申告する。
  - 文字盤に「見えるのは境目まで」と渡す方法は取らない。文字盤は要素の矩形をクリップで切り詰めて登録する（`HandsFace.cpp`、`DigitalWatchFace.cpp`）。
    そのため境目が要素の上を通る間、その要素が毎フレーム変わったことになり、要素の上端から境目までを毎回描き直してしまう。
  - 静止時の環境を渡せば、文字盤の要素は変わらない。毎フレーム描くのは新しく現れた帯だけになる。
- 最後に範囲を戻す。どの画素も一度ずつ描かれているので、最後に全面再描画はしない。
- 負荷の見込み: 1フレームで最も大きいのは、成立直後の最初の動き（約50行、画面の約1/9）である。アニメーション全体（約37フレーム）で描く画素は、およそ1画面分になる。
- 途中のフレームでは、要素の記録（描いたことになっている）と実際の画素（範囲の外は前の画面のまま）が一時的に食い違う。
  これがこの方式の唯一の弱点なので、描画検証で、途中と最後の画素を全面描画と比べる（6章）。
- 統計表示は、幕の間は範囲の外へ描かない。チップが範囲に入ってから描き直す。
- 計測用の分類（`FrameActivity`）に、ホームジェスチャー（帯と幕）を足す。

### 2.7 アイコン資産

## 3. 確認の経緯

2026-10-07に次のとおり確認し、1章へ反映した。

1. A+B に加えて、タッチだけでもホームへ戻れるようにする。上端から下へのスワイプで、文字盤が指定する色の帯を出す。Y座標だけで判定した一定の距離を越えて離すと、アニメーションでホームへ戻る。
2. アニメーション中のアプリ画面は止まっていてよい。文字盤を上から下へ描き、下の部分は書き換えない。描画の仕組みにこのジェスチャー専用の記述が増えることは、システムの重要な機能なので許容する。
3. 指を離した瞬間に帯は消え、文字盤に切り替わる。
4. 帯のアイコンはチェックではなく、文字盤を表す`ic_watchface`。`WatchFace`に`homeGestureBackground`と`homeGestureForeground`を足す。
5. 帯の最大の高さは80px。指が下にあるほど高く、上の方ではよく付いてきて、下の方では鈍くなる傾斜を設ける。
6. アイコンは、その時の帯の天地中央に置く。帯が低いときは上下で切れる。
7. 成立後のアニメーションは急なイーズアウト。
8. A+B でも帯を出す。600msかけて、イーズインアウトで80pxまで広げる。
9. `homeGestureBackground()`の既定は黒。文字盤ごとの色は1.1節の表のとおり（計画の初版で出した強調色の案は採らない）。
10. ホームへ戻らなかったときは、帯が急なイーズアウトで100msかけて縮む（初版では「すぐ消す」としていた）。
11. 幕はquintのイーズアウトで600ms（初版では300ms）。
12. 対象の画面は2.1節・2.4節の案のとおり。スワイプはアプリ画面だけ、A+B の帯はアプリ画面と一覧で出し、時計では出さない。

- [ ] **14-1: 入力の判定と状態**
  - `Events`の同時押しの情報を足す。`HomeGesture`の状態・純関数・期限を作り、`ScreenManager`へ接続する。
  - この段階では、成立したらすぐにホームへ切り替える（今の A+B と同じ全面再描画）。

  - ホストテスト（6章）。
- [ ] **14-2: 帯の描画と、実機での上端の確認**
  - `WatchFace`の色、アイコン資産、`HomeGestureLayer`を作る。帯（縮むアニメーションを含む）の画素一致を確かめ、画面写真（`render_shots`）で4つの文字盤の帯を見る。
  - 実機で、画面の縁から指を滑り込ませたときに上端の帯の範囲（y ≤ 40px）で拾えるかを確かめる。
    最初に読めたタッチの位置を一時的なログで記録する（パッチで当て、製品版には残さない）。
    結果を見て、範囲・成立の位置・帯の曲線を調整する。機器への書き込みは、実行前にユーザーへ確認する。
- [ ] **14-3: 文字盤が現れるアニメーション**
  - `Renderer`の範囲の口、幕の合成、`HomeLayer`の帯の申告、統計表示の扱い、割り込みを作る。
  - 4つの文字盤 × 開始時の画面で、途中と最後の画素一致を確かめる（6章）。
- [ ] **14-4: 実機確認と完了判定**
  - 操作感（帯の付き方、成立の位置、幕の速さ）、フレーム時間、割り込み、既存の操作への影響を確かめる。
  - 検証記録と設計書を更新する。

各段階の結果は`14-n-validation.md`へ記録する。段階ごとの詳細計画（`plan-14-n.md`）は着手時に作る。

## 6. 検証と完了条件

### ホスト検証

- 所有:
  - アプリ画面で、上端の帯の範囲で始まったタッチが画面へ1つも届かないこと（`TouchStart`・ドラッグ・タップ・離したとき）。範囲の外で始まったタッチは今どおり届くこと。
  - 時計と一覧では上端のタッチを取らないこと（一覧の先頭での下引きが今どおり動くこと）。
  - 外部起動の確定中は帯も成立もないこと。消灯からの復帰に使ったタッチでは成立しないこと。
- 帯の高さ: h(0)=0、上端での傾きが1、単調に増え、80を越えないこと。X座標によらないこと。
- 成立: y=119 で離すと成立しないこと。y=120 で離すと成立すること。成立は1回だけで、ホームの回数が1つ増えること。
- 縮む:
  - 成立しなかったとき、帯が離した時点の高さから100msで0になり、その後は期限を持たないこと。形はquintのイーズアウトであること。
  - 縮む間も画面へ入力が届くこと。縮む途中で始まった上端のスワイプが、その指の帯に切り替わること。
  - タイマーの満了と消灯では、縮めずにすぐ消えること。
- A+B:
  - アプリ画面と一覧で帯が出て、時計では出ないこと。
  - 0・300・600msの高さ（0・40・80）と、イーズインアウトの形。
  - 600ms未満で離すと帯が100msで縮み、A/B の短押しにもならないこと（今どおり）。
  - スワイプ中に A+B が始まると、スワイプが取り消されること。
- 幕:
  - 成立時に画面が退場すること（タイマーの満了の解除、未保存の編集の破棄、輝度のプレビューが戻ること）。
  - 境目が成立時の帯の高さから始まり、600msで下端に着き、その後は期限を持たないこと。期限は16ms間隔で、形はquintのイーズアウトであること。
  - 幕の間の入力が画面にも一覧にも届かないこと。その間に始まった押下が、終わった後に届かないこと。
  - タイマーの満了で打ち切られて全面再描画になること。消灯で打ち切られること。
- 文字盤の色: 既定値（黒・白）と、4つの文字盤の値。Forest は時刻で空の色が変わること。Noonish は針の動きで上端の中央の領域が変わったとき、その色に変わること。

### 描画・実機検証

- 帯: いくつかの高さ（アイコンより低い・アイコンと同じ・80px）で、全面描画と画素一致すること。帯が縮んだときに、アプリ画面が正しく戻ること。
- 幕:
  - 4つの文字盤 × 開始時の画面（タイマー、設定、一覧）で確かめる。
  - 途中のフレームでは、境目より上が時計の全面描画と、下が開始前の画面の画素と一致すること。最後のフレームが全面描画と一致すること。
  - 途中で分が変わる場合、帯の申告と要素の変更が重なる場合、`FramePlan`の容量を超えた場合も確かめる。
- 負荷: 幕の各フレームの描画時間と更新範囲を記録する。最大のフレームが16ms間隔に収まることを確かめる。帯の間のフレーム時間も記録する。
- 実機:
  - 画面の縁から始めたスワイプを拾えること（14-2の記録）。
  - 成立の位置と帯の付き方が自然であること。幕が途切れずに動くこと。
  - 鳴っているタイマーの上でのスワイプと A+B。動いているストップウォッチの上でのスワイプ。
- 既存の操作への影響がないこと: A+B の600ms、一覧の先頭での下引き、時計の長押し、画面内のドラッグ（設定のスクロール）、消灯からの復帰。
- 静止時の消費電力が変わらないこと（帯と幕の期限は、動いている間しか持たない）。
- 通常版・英語版・描画検証版のビルド、`verify_build.py`、既存の回帰テスト。
