# wararyoLauncher アーキテクチャ

2026-09-24更新。作業9-4と命名整理後の製品版 `src/` を対象とする。
実装の構成と拡張時の判断を説明する文書であり、性能目標の達成記録ではない。
要求・履歴は [plan.md](plan.md)、リファクタリングと実機確認の残項目は [作業9](task9/plan.md) を参照。
`measurement/` は測定用の試作で、製品版とは別の構成である。

## 1. 全体構成

ESP-IDF上のC++ファームウェア。M5Unifiedが機器アクセス、M5GFXが描画を担当する。
UIの状態更新と描画はCPU1の単一UIタスクで行い、外部ファームウェアの検査だけをCPU0のワーカーへ分離する。
画面ごとにタスクを作らず、入力と更新期限を処理する一つのループで全体を動かす。

| 場所 | 役割・主な入口 |
|---|---|
| [main.cpp](../src/main.cpp) | ハードウェア初期化、永続オブジェクトの生成と接続、実行ループ |
| [host/](../src/host/) | 製品全体の構成、画面管理、描画構成。`HostApplication`、`HostRuntime`、`ScreenManager`、`HostRenderer` |
| [features/home/](../src/features/home/) | 時計、文字盤の寿命管理、時計・電池の表示データ供給 |
| [features/launcher/](../src/features/launcher/) | ホーム↔一覧の遷移、起動先をリスト行へ変換、一覧固有の資産 |
| [features/stopwatch/](../src/features/stopwatch/) | 計測操作、表示モデル、配置、描画 |
| [features/settings/](../src/features/settings/) | 設定トップのリスト、各編集画面、輝度プレビュー |
| [features/external/](../src/features/external/) | 外部スロットの詳細と起動確認 |
| [ui/list/](../src/ui/list/) | 機能を知らないリスト操作・配置・描画・キャッシュ |
| [ui/rendering/](../src/ui/rendering/) | `Renderer`、`FramePlan`、矩形・表示領域などの共通描画基盤 |
| [ui/graphics/](../src/ui/graphics/)、[ui/overlays/](../src/ui/overlays/) | フォント・文字整形・画像型、トースト・統計表示 |
| [services/](../src/services/) | 画面の寿命から独立した計測・時刻の状態と処理 |
| [input/](../src/input/)、[power/](../src/power/) | ボタン・タッチの意味イベント化、消灯状態と期限 |
| [hal/](../src/hal/) | 単調時計、機器I/O、待機・入力割り込みの実装 |
| [storage/](../src/storage/) | 設定レコードとNVS保存 |
| [multifirm/](../src/multifirm/) | 外部スロットの検査結果、非同期検査、起動APIとの境界 |
| [core/](../src/core/) | 入力や描画に依存しない共通の時間型 |

依存の基本は「ホストが機能を組み立て、機能が共通UIやサービスを使う」。共通UIから具体的な機能、
`LaunchRegistry`、`FrameModel`、NVS、OTAを参照しない。機能はホストが提供する `Screen` などの契約を利用する。
機能間の連携はホストで調停し、別画面の内部状態を直接変更しない。

### 所有権と寿命

[HostApplication](../src/host/HostApplication.h) は `StopwatchService`、`RuntimeSettings`、`HostShutdown`、
`ScreenManager`、`HostRuntime` を所有する。宣言順に構築し、借用側のRuntime・画面が先に破棄される。
`ScreenManager` は具体的な画面と `LauncherController` を所有するが、計測サービスは借りる。

`main.cpp` はHAL、`HostRenderer`、時刻・設定・スロットのサービス、`HomeDataSource` を生成して注入する。
`HostRenderer` は各描画レイヤーと文字盤管理を所有する。大きい描画オブジェクトと `HostApplication` は
staticに置き、8KiBのUIタスクスタックを圧迫しない。新しいサービスも、その状態が必要な寿命に合わせて所有者を決める。

## 2. 実行ループと状態の流れ

[HostRuntime](../src/host/HostRuntime.cpp) の `step()` → `wait()` を繰り返す。

1. 単調時刻を取得し、必要ならHALから入力を読む。`InputController` が `Events` に変換する。
2. 消灯状態を更新し、イベントを `ScreenManager` に渡す。
3. スロット検査の公開結果を取り込み、期限が来たUSB状態を取得する。
4. 点灯中は表示中の画面・アニメーション・通知の期限を処理する。
5. 状態変更または表示期限があれば `FrameModel` と `WatchData` を作り、`HostRenderer` に渡す。
6. 起動確定の保留要求を処理する。「起動中」の描画より後に実行する。
7. 最も早い次回期限まで、通知で中断可能な待機に入る。

ここには二段階の変更判定がある。Runtimeの `dirty_` は「モデルを再評価する必要がある」という意味であり、
液晶転送を確定しない。再評価後に `FramePlan` が実際のピクセル変更を判定し、変更がなければ描画・転送を省く。

`FrameModel` は各機能の小さな表示モデルの合成である。各Layerには自分のモデルだけを渡す。
フレーム準備後からpaint完了まで入力を変えず、文字列や行配列を借用する場合はその期間より長く保持する。
一時変数の文字列や行配列へのポインタをモデルに入れない。

## 3. 「アプリ」、画面、起動先の区別

| 用語 | コード上の意味 |
|---|---|
| Host | wararyoLauncherファームウェア全体。`HostApplication`、`HostRuntime`、`HostRenderer` |
| Feature | 内蔵機能の実装単位。`features/stopwatch/` など |
| Screen | 内蔵の操作画面。入退場・イベント処理・更新期限の契約 |
| Launch target | 一覧から選択する起動対象。`LaunchTargetId`、`LaunchEntry`、`LaunchRegistry` |
| AppList | ユーザーに見えるアプリ一覧。内蔵機能と外部スロットを並べる |
| External app | 別パーティションにある別ファームウェア。起動するとホストから再起動で切り替わる |

内蔵機能と外部ファームウェアは同じ実行モデルではない。共通化しているのは一覧の入口である。
現在の [LaunchRegistry](../src/host/LaunchRegistry.h) はストップウォッチ、設定、外部1〜3の5項目。
`LaunchTargetId` は起動先、`ScreenId` は現在の表示画面を識別する。外部3スロットは一つの詳細画面を共有する。

### 画面の契約

[Screen](../src/host/Screen.h) は次を持つ。

| メソッド | 拡張時の注意 |
|---|---|
| `available()` | 依存サービスが未接続なら開かない |
| `enter(now)` / `exit()` | 表示用状態を準備・終了する。画面を閉じても継続する業務状態はサービスに置く |
| `handle(events, now)` | 操作し、`ScreenOutcome` で変更・退場・通知などを返す |
| `nextUpdate()` / `tick(now)` | 自発的な表示更新の絶対期限。静止時は `INT64_MAX` |
| `active()` | ドラッグや整定など、表示内容が動いているかを返す。消灯禁止を意味しない |
| `exclusive()` | ホームを含む入力を一時的に禁止する。現在は取り消せない外部起動確定中だけ |

A/Bは `next` / `decide` として届くが、ストップウォッチでは左/右操作など画面が意味を決める。
A+Bの連続600ms長押しは共通のホーム操作で、通常は個別画面より優先する。
ホーム・一覧のジェスチャー所有権は `LauncherController`、各画面内の操作はその画面が管理する。

### 内蔵機能を追加する手順

1. `features/<name>/` に `Screen`、表示用 `Model`、`Layout`、`Layer` を作る。
   計測のように画面外でも継続する状態はサービスへ分け、`HostApplication` 等から注入する。
2. `LaunchTargetId` と `LaunchRegistry` に項目を追加する。既存IDの数値を変えず、配列の位置から起動先を推測しない。
   現在のenumは暗黙連番なので途中挿入を避けるか、既存値を明示して維持する。
3. `ScreenId` と `ScreenManager` の所有メンバー・初期化・`launch()`・モデル合成を追加する。
   現在のホーム処理は各画面の `exit()` を列挙しているため、新画面も終了対象に含める。
4. `FrameModel`、`FrameComposer` の可視性・`FrameOrder`、`HostRenderer` のLayer所有・準備・対応表を追加する。
   必要なら `FrameActivity` と診断の分類も追加する。
5. アイコンを追加する場合は `IconId` と [build_icons.py](../tools/build_icons.py) の `ICONS` を対応させ、資産を再生成する。
   `IconId` は埋め込み画像の索引なので既存順序を変えない。新しい表示文字にはフォントの収録範囲も確認する。
6. [CMakeLists.txt](../src/CMakeLists.txt) と [test_runtime.py](../tools/test_runtime.py) のソース一覧を更新し、
   入退場・ホーム・更新期限・サービスの寿命を検証する。描画を追加したら差分描画の診断も増やす。

Registryへの追加だけでは画面は動かない。ホストで起動先・モデル・描画を明示的に接続する構成であり、
動的プラグイン探索や自動登録の仕組みは設けていない。

### 外部ファームウェアの扱い

[SlotService](../src/multifirm/SlotService.h) がUI側の境界、[MultiFirmAdapter](../src/multifirm/MultiFirmAdapter.cpp) が実機実装。
ホストは `ota_0`、既存の外部スロットは `ota_1`〜`ota_3`。外部ファームウェアを既存スロットへ入れる場合は
新しい内蔵Screenを作らず、MultiFirm互換の成果物を用意する。検査で取得した名前・状態が既存行に反映される。
書き込みは [READMEの手順](../README.md) と [upload_guard.py](../tools/upload_guard.py) に従う。
スロット数自体を増やす場合は、パーティション配置・MultiFirm側の契約・`SlotCount`・Registryを別途まとめて見直す。

初回表示後にCPU0ワーカーがスロットを直列検査し、カタログをmutexで保護して公開する。
世代番号とUIタスク通知で変更を伝え、UI側がコピーを取り込む。ワーカーから画面や計測状態を操作しない。
空・破損スロットも詳細画面は開けるため、一覧では薄く表示して理由を詳細側で説明する。

起動は「確認→起動中表示→UIタスクで同期的に起動確定」の順。
成功は再起動で終わり、失敗だけが戻る。起動先の確定後に `HostShutdown` が単調時計を読み、計測を停止する。
検査失敗・起動失敗・通常の画面退場では計測を止めない。別ファームウェア実行中の計測継続・復元は現在の契約に含まれない。

## 4. 描画とFramePlan

描画計画の型名は **`FramePlan`**（Frame＝フレーム）。実装は [Element.h](../src/ui/rendering/Element.h) と
[Element.cpp](../src/ui/rendering/Element.cpp)。機能を知る `HostRenderer` と、機能を知らない共通 `Renderer` を分けている。

### 一フレームの処理

1. `FrameComposer` がモデルから表示領域・可視性を決定する。時計の可視性はRuntimeの期限判断にも同じ関数を使う。
2. `HostRenderer` が各Layerへモデルを固定し、画面切替なら全面再描画を要求する。
3. 全Layerの `plan()` が `FramePlan::add()` で要素の矩形とfingerprintを登録する。
4. `resolve()` が変更と重なりを解決し、描画する要素と変更領域を確定する。
5. 変更がある場合だけ `startWrite()`。全面消去、または変更要素の旧矩形を黒で消す。
6. 各Layerを背面から `paint()`。最後に統計オーバーレイを描き、`endWrite()` で転送を完了する。

順序はホーム→一覧→設定/外部詳細/ストップウォッチ（表示中のもの）→トースト→統計。
描画時間は計画開始から `endWrite()` 後までを計測し、転送コストも含める。

### 変更検出と重なり

Layerはフレームをまたいで `Element` を保持する。そこには前回矩形・fingerprint・有効フラグがある。
初回、矩形の変化、fingerprintの変化が再描画の起点になる。fingerprintには文字・色・選択状態など、
同じ矩形でも見た目を変える値を含める。座標変化は矩形でも検出できる。

変更要素だけを描くと、旧領域を消したときに別の文字や前景まで消えたり、再描画で前景を上書きしたりする。
そこで `resolve()` は旧消去領域・新描画領域に重なる要素へ再描画を伝播し、対象が増えなくなるまで繰り返す。
その後、元の描画順で描き直して重なりを復元する。背景色は現在黒が前提であり、
背景画像を導入する場合は黒塗り消去の契約から見直す必要がある。

`dirtyBounds()` は消去・再描画する全矩形を囲む一つの矩形。
これは任意の領域を描くだけで背景復元できるAPIではなく、確定した描画の影響範囲である。
現在のパネルはフレーム内の変更を囲む領域を転送するため、離れた場所への小さな描画でも転送範囲を広げ得る。

### 非表示・全面再描画・容量超過

- 要素が消えたときは空矩形を登録して旧領域を消す。一覧は非表示でも表示スロットを空で登録する。
- 画面全体が切り替わり、以前のLayerが登録されなくなる場合は `FrameComposer` が全面再描画を要求する。
  設定メニュー↔編集画面のような同一画面内の切替は、そのLayerが履歴無効化と全面再描画を担う。
- 起床・文字盤切替など、画面と履歴の一致が保証できない場合も全面再描画する。
- `FramePlan` は固定容量32。超過時は切り捨てず全面再描画へ切り替える。
  `add()` が `-1` を返した要素も、`shouldPaint()` が全面時にtrueを返す契約で描けるようにする。
  新Layerで「handleが負なら描かない」としてはいけない。

`paint()` は登録した矩形・clipの範囲に描画を収める。はみ出すと消し残しや統計表示の復元漏れにつながる。
独自の画面全消去をLayerへ追加せず、必要なら計画段階で `forceFull()` を要求する。

### 共通リストとキャッシュ

[ListController](../src/ui/list/ListController.h) は選択・スクロール・慣性と更新期限を管理する。
[ListLayout](../src/ui/list/ListLayout.h) は配置とヒットテストを共有し、
[ListView](../src/ui/list/ListView.h) が可視行の描画・文字整形・文字スプライトを担当する。
行は `RowId`、文字列、任意のアイコン、選択可能性などで表し、何を起動するかは所有画面が判断する。

一覧と設定トップは別々のController/Viewを持ち、同じ実装を使う。編集画面は従来の個別Layerである。
リストは表示スロット8個を保持し、全件分の描画キャッシュを作らない。可視行がスロット数を超える場合は
全面再描画・直接描画へ切り替え、行を欠落させない。文字スプライトはPSRAMを使用し、確保失敗時は直接描画へ戻る。
退場時はアニメーション期限を止める。一覧は戻り位置を保持し、設定は編集画面との往復では保持、設定への新規入場では先頭へ戻す。

### 統計表示

`StatsOverlay` は `FramePlan` の外で最後に描く。表示値の変更、初回、または変更領域との重なりがある場合にだけ更新し、
統計表示のために転送範囲を毎回広げない。内部RAMの小さなキャッシュが使えなければ直接描く。
独立した描画タイマーは持たず、通常の描画に追従する。現仕様では有効化後に無効化するUIはなく、再起動で解除される。

## 5. 文字盤を追加する

[WatchFace](../src/features/home/WatchFace.h) を実装し、`features/home/faces/` に配置する。
`begin()` / `end()` で資源を管理し、`plan()` / `paint()` は `WatchData` と `DrawRegion` だけを入力にする。
文字盤からRTCや画面管理を直接読まない。`DrawRegion` のoffsetとclipを守り、ホーム↔一覧の遷移中にも正しく切れるようにする。

`nextUpdate()` は次に表示が変わる絶対時刻を返す。秒表示なら秒境界など、表示精度に必要な期限だけを要求する。
既定のDigitalWatchFaceを所有する `HomeLayer` は最大4個を登録でき、ID重複と容量超過を拒否する。
追加インスタンスを `HostRenderer::registerFace()` に渡し、`selectFace()` で選択する。
外部登録の文字盤は借用されるため `HomeLayer` より長く生存させる。寿命を動的にするなら所有方式も変更する。

切替時は旧文字盤を `end()` し、新文字盤の初期化に失敗したら旧文字盤をキャッシュ無効で再初期化する。
復旧にも失敗した場合は文字盤なしになる。切替は全面再描画を要求する。
現在は選択を保存する設定UIはないため、追加登録とユーザー向け切替UIの実装は別作業となる。

## 6. 時刻・計測・設定

- **単調時刻:** `TimeUs` はマイクロ秒単位。実機は `esp_timer_get_time()`。入力判定・アニメーション・期限・計測に使う。
- **実時刻:** `TimeService` は起動時にRTCを検証し、通常表示ではシステム時計を読む。RTC/UTCとJST表示を分ける。
  時刻未設定は不明として表示し、毎フレームRTCへI2Cアクセスしない。
- **計測:** `StopwatchService` は開始時刻と累積値から経過時間を求め、画面の更新回数に依存しない。
  ホーム移動・消灯でも計測は続く。表示中の実行状態だけ25ms（40Hz）の表示期限を持つ。
- **設定:** `SettingsStore` は値の検証とレコード化、`NvsBackend` は保存を担当する。
  保存成功後に現在値を更新し、失敗時は前の値を維持する。未知のスキーマは勝手に上書きしない。
- **輝度プレビュー:** 編集中の値から実効値を返し、Runtimeが適用する。キャンセル・ホームで編集を終了すると保存値へ戻る。
- **実行時設定:** 統計の有効化などは `RuntimeSettings` に置く。画面は `ScreenOutcome` で要求し、ホストが反映する。

## 7. 省電力と期限管理

現在の製品設定はCPU最大240MHz・最小80MHzのDFS、tickless idle有効、自動light sleep有効。
`beginPowerManagement()` と [sdkconfig.defaults](../sdkconfig.defaults) が設定元である。
消灯は液晶のsleepと輝度0であり、MCUのdeep sleepを意味しない。
light sleepは `ESP_PM_NO_LIGHT_SLEEP` のロックで既定では禁止し、消灯中かつVBUSの読み取りがUSB給電なしを示すときだけ
`HostRuntime` が `Hal::setLightSleepAllowed()` で許す。パネルのsleep後に許可し、パネルを起こす前に取り消す。
起床は入力の割り込み（A・B・タッチINT）と期限による。

### 起きる必要があるときだけ処理する

| 処理 | 現在の期限・条件 |
|---|---|
| 入力 | 押下・タッチ追従中は10ms。割り込み後100msも追従し、待機時は割り込みで再開 |
| USB状態 | 1秒ごと。消灯中も継続 |
| 時計 | 時計が実際に見える場合だけ文字盤とデータ供給側の期限を採用 |
| 電池情報 | `HomeDataSource` が描画経路で最大30秒ごとに取得。消灯中は取得しない |
| リストアニメーション | 動作中は16ms間隔を要求。補間はフレーム数ではなく経過時間で計算 |
| ストップウォッチ | 表示中・計測中のみ25ms。非表示でも計測の状態は保持 |
| 消灯 | 最終入力から設定時間。初期値30秒、選択肢15/30/60/180秒 |

`HostRuntime::wait()` は入力・USB・消灯・表示中の画面・時計の期限の最小値まで待つ。
消灯中は画面更新とその期限を待機対象から外す。過負荷で期限を超えても最低1msの待機を要求し、
HALでtickへ切り上げてidleタスクに実行機会を与える。遅れた全フレームを追いかけて再生しない。
新機能は「毎ループ描画する」のではなく、状態変更と `nextUpdate()` で更新を要求する。

### 入力割り込みと復帰

GPIO 2（A）、1（B）、13（タッチINT）のlowレベル割り込みでUIタスクを通知する。
ISRではI2Cや描画を行わず、発火した割り込みを一時停止して通知するだけ。ピンがhighへ戻ったものを待機前に再有効化する。
`ulTaskNotifyTake()` で待ち、外部スロット検査の完了通知でも待機を終了できる。
割り込み初期化に失敗した場合はHALが待機を最大10msに制限し、ポーリングで操作性を維持する。

消灯復帰時はパネルを起こし、輝度を再適用して全面再描画する。
復帰に使ったタッチは消費し、その一押しで背後の項目を誤って決定しない。
`active()` がtrueでも最終入力からの消灯期限は優先されるため、動いている表示を理由に無期限点灯にはしない。

CPUの待機時間を増やすことがDFSの効果にもつながる。独自のbusy wait、不要な定期タイマー、
毎フレームのI2C読出し、不要な画面外要素の描画を増やさない。シリアル接続の有無は消費電力の測定条件に含める。
電力・描画性能の現状や未達項目は [作業8](task8/plan.md) と [作業9](task9/plan.md) を参照し、構造改善だけで達成扱いにしない。

## 8. 変更後の確認と調査の入口

| 目的 | 入口 |
|---|---|
| 状態・操作・期限の回帰 | `python tools/test_runtime.py`。PC上で6スイートをコンパイル・実行 |
| 製品ビルド | `pio run -e m5stopwatch` |
| 実機の時間計測 | `m5stopwatch-measure`。実データと描画/USB診断 |
| ピクセル・キャッシュ・文字盤寿命 | `m5stopwatch-render-check`。合成データと描画診断 |
| 過負荷時のidle確認 | `m5stopwatch-diagnostics`。意図的な40ms負荷を追加 |
| 電池駆動の記録 | `m5stopwatch-drain` |
| パーティション・ビルド条件の検証 | `python tools/verify_build.py --environment <環境名>`。機体への書き込みなし |

ホストテストは実機M5GFX・QSPI転送を実行しない。Layerの変更は実機の全面描画とのピクセル比較、
消し残し、確保失敗時のフォールバック、退場後の期限、操作中の転送時間まで確認する。
`FramePlan` の容量超過や文字盤の初期化失敗も診断対象に含める。

ビルド・テスト・実機の大量ログは最初にファイルへ保存し、終了コードと必要な行だけを取得する。
既存ログを上書きせず、作業・構成・測定区間を名前で区別する。詳細は [AGENTS.md](../AGENTS.md)。

設計を変えたときは、この文書の所有権・期限・登録手順を実装と一緒に更新する。
過去の検証記録は当時の証跡として維持し、現在の構成との対応は [命名整理](task9/naming-cleanup.md) を参照する。
