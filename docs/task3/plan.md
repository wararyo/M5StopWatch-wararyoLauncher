# 作業3：描画基盤・WatchFace・5項目一覧の実装計画

作成日: 2026-09-20。設計の基準は [全体計画](../plan.md) の4〜7章・作業3。
本書は作業2の実機検証が合格した前提の計画であり、実装・検証完了の記録ではない。
実装開始時には作業2の検証で判明した修正を反映済みであることを確認する。

## 到達点と範囲

起動するとデジタル時計が表示され、上スワイプ・APPSタップ・A/Bで5項目の一覧へ移動できる。
一覧は指に追従し、解放後に位置補正する。Aで選択を循環し、Bまたは項目タップで決定する。
ホーム、消灯復帰、画面の重なりを含め、差分描画が全面再描画と一致する状態まで仕上げる。

RTC・設定保存・設定画面は作業4、計測は作業5、スロット走査・外部起動は作業6に残す。
作業3では全5項目を選択できるが起動は不可とし、行に「未実装」または「未確認」を表示する。
決定時は理由を短い通知で示し、架空のアプリ画面へ遷移しない。外部の未確認状態を空・破損と表示しない。
時計には表示データの注入境界を設け、通常版では未取得の時刻・電池を不明表示にする。
検証用の時刻・電池・充電状態は診断版だけに注入し、起動ログで検証データ使用を明示する。

## 実装順序

### 3-1. 表示契約とRuntime接続

- M5GFXに依存しない不変の表示モデルを定義する。画面、選択、スクロール、遷移量、通知、時計データ、表示領域を含める。
- 描画インターフェースをRuntimeへ注入し、製品RendererとPC用の偽Rendererを差し替え可能にする。`Hal::draw` にある製品画面の責務を移す。
- UIタスクが画面状態・Renderer・WatchFaceを所有する。ScreenManagerはHALや描画APIを呼ばない。
- 64bit単調時刻を画面更新へ渡し、状態更新→スナップショット生成→描画→次期限の順序を明確にする。
- 次期限は可視画面の表示データ・WatchFace・補間・通知消去の最小値。期限処理後は未来の期限または期限なしへ進める。
- 入力ポーリングだけではdirtyにしない。USB状態変化も、それを表示していない時計・一覧の再描画にはつなげない。
- 画面OFF中は描画・レイアウトと表示用期限を停止。復帰時に最新データを取得して全面無効化する。最低1tickの待機と過負荷時の追いつき防止を維持する。

確認: 偽時計と偽Rendererで静止時の描画・レイアウト呼び出しが0回、期限到達時の更新が1回、消灯中の表示更新が0回になる。

### 3-2. Element / FramePlan / Rendererの移植

- 全レイヤーのplan→影響解決→全消去→背面からpaint→転送の順序を実装する。通常版に全画面の中間スプライトを追加しない。
- 旧位置・新位置・内容変更に加え、再描画で上書きされる前景への影響を確認する。消える要素は空矩形として登録するか明示的に履歴を破棄する。
- 時計、最大5行、ヒント、通知を含む最大要素数と固定配列の余裕を根拠付きで定義する。容量超過を黙って欠落させない。
- 超過フレームは差分計画を使わず、全表示モデルを走査する全面描画経路へ退避する。単に同じ満杯のFramePlanを再実行しない。次フレームの履歴も再初期化する。
- 画面切り替え、復帰、通知の出現・消去、WatchFace変更は全面無効化を許可する。通常の移動では差分描画を使う。
- 円の端点・文字の張り出し・クリッピングを描画矩形へ含める。描画矩形と操作の当たり判定は用途に合わせて区別する。

確認: 矩形・カリング・削除・重なり・容量超過の検証を用意し、実機ピクセル検証へつなぐ。

### 3-3. WatchFaceとデジタル時計

- 試作の `begin / plan / paint / nextUpdateDelayMs` を基に、安定ID登録と終了時のキャッシュ解放を追加する。通常版はデジタル1種類で、選択UIは作らない。
- plan/paintで同じデータを使う。WatchFaceはRTC・電源・NVSを直接参照しない。
- 実表示サイズから配置と円形安全領域を決め、試作の中心234等の固定値を置換する。見た目は `docs/WatchFaceDigital.png` を基準にする。
- 英語日付・24時間の時分・電池・充電状態・APPSを描く。無効時刻は `--:--`、不明電池は不明表示とし、0%に置き換えない。
- 時刻文字キャッシュを初期化時に確保し、失敗時は直接描画する。毎フレームの動的確保を避け、使用量・確保先・解放を確認する。
- 注入した時刻から分境界の期限を計算し、Runtimeの単調時刻期限へ接続する。非表示中は時計だけの期限で再描画しない。実時計の同期と電池30秒取得は作業4で接続する。

確認: 分更新、日付変更、有効/無効時刻、不明電池、充電変化、キャッシュ失敗、テスト用WatchFaceへの差し替えを検証する。

### 3-4. 5項目一覧とジェスチャ

- ストップウォッチ、設定、外部アプリ1〜3を表示。外部アイコンは数字とし、配列位置からスロットを推測しない。
- `docs/AppList.png` に沿い、行の縦位置に応じた横位置と表示可能幅を計算する。画面外をカリングし、長い名前は文字境界を壊さず幅で省略する。
- 固定日本語UIに必要なグリフと代替文字を揃え、フォント追加後のFlash容量を確認する。任意Unicodeへの対応や外部詳細画面は作業6へ残す。
- 同じレイアウト情報から描画・行の当たり判定・選択項目の可視化を行う。円の外や画面外の行をタップ対象にしない。
- 時計の上ドラッグは指追従、解放時は短辺比 `50/468` を初期確定しきい値にする。タップ抑止用の作業2の短辺/50とは区別する。
- 補間は約16ms周期を初期値とし、開始時刻と経過時間から進行量を求める。遅れたフレームを追いかけない。期間・曲線は定数として実機調整する。
- 一覧のドラッグは範囲内スクロールと解放後の位置補正。先頭からの下ドラッグだけ時計への復帰操作にする。操作中にモードを往復させず、途中で先頭へ到達した場合の復帰は次のジェスチャからとする。
- Aは5件を循環し選択行を見える位置へ移動。B/項目タップは利用不可理由を通知する。ドラッグ後のタップは発火させない。
- ホームはドラッグ、補間、通知、選択を解除して時計へ戻す。既存の残りタッチ消費を維持する。

確認: 上下の確定/キャンセル、先頭/末尾、5→1循環、スクロール後のタップ、補間中のホーム、利用不可項目の決定をPCで検証する。

### 3-5. ピクセル検証・性能計測・実機手順

- 描画検証専用のPlatformIO環境を追加し、通常版の依存固定・書き込み保護・容量検査を継承する。既存の40ms過負荷注入とは分け、性能測定へ混入させない。
- 試作RepaintCheckの24パターンを5項目へ適応して残し、往復遷移、両端、選択、長い日本語、通知の重なり/消去、復帰、WatchFace差し替え、キャッシュ失敗、容量超過を追加する。
- 同一スナップショットの差分結果と強制全面描画結果を比較する。フレーム履歴を積み上げた連続操作も検証し、不一致数・座標・条件を記録する。
- 比較バッファの確保失敗や読出し不成立は「検証不能」とし、合格にしない。既存の非黒画素チェックも保持する。バッファ・起動ベンチは通常版に含めない。
- Runtimeを含む実動作でスクロール・往復遷移を各60秒以上測定する。描画処理時間と描画完了間隔を別々に集計し、平均・p95・最大・33.3ms超過数・実fpsを出す。
- 入力→表示と復帰時間は測定の始点・終点を明記し、初回描画・復帰を定常区間から分離する。静止時は描画回数とレイアウト回数も記録する。
- 内部RAM/PSRAMの空き・最大連続領域・UIタスクのスタック余裕を記録し、反復遷移とWatchFace初期化/終了でリークを確認する。
