## 1. 実機での確認

| 項目 | 結果 |
|---|---|
| 精度（100歩） | 手で数えた100歩に対して94歩（約6%少ない） |
| 精度（1日） | 外出のある1日で、スマートフォンの歩数計5,612歩に対して6,948歩（約24%多い）。客先からオフィスに着いた時点の差は約200歩で、差の大部分はデスクワーク中の手の動きを歩数として数えたものと見られる |
| 4時の区切り | 前日の確認の後、翌朝に0歩から数えていた |
| 外部アプリをまたぐ引き継ぎ | 外部アプリから戻った後も今日の歩数が保たれた。外部アプリの実行中に歩いた分は増えなかった |
| 文字盤の情報 | 閾値を一時的に200歩にした確認用ビルドで、文字盤に歩数の行が出ることを確かめた。確認の後、通常版に戻した |
| 回帰 | 手首のウェイク・タイマー・ストップウォッチなど、既存の動作に問題は見られなかった |
| 保存の契機 | シリアルログの`[Pedometer] saved`が、消灯時と外部アプリの起動確定時にだけ出て、ほかの契機の保存はないことを確かめた |
| 消灯中の電流 | 13-1で測定済み。歩数計なし24.0mAに対し、歩数計あり（性能モード）24.0〜24.5mA（[13-1の検証記録](13-1-validation.md)3.4節） |

精度はユーザーが満足できる水準と判断したので、歩数の調整値はイメージの既定値のまま使う（計画2.1節）。
デスクワーク中の手の動きを数えることは、手首に着ける歩数計として受け入れる。

## 2. 計画から省いたもの

- 1日の保存回数: 回数そのものは数えていない。1日分を数えるには、USBをつないだままにするか、回数を数える確認用ビルドが要る。
  保存が消灯時と外部起動確定時に限られ、値が変わらない消灯では書かないことをログで確かめたので、それで足りるとした（2026-10-09、ユーザー判断）。
  書き込みは多くても消灯の回数までで、NVSの消耗は問題にならない見込み（計画2.5節）。
- 4時の区切りの合わせ直しのログ: 区切りは翌朝の0歩で確かめた。区切りの10分前・1分前の合わせ直しは、ホストテストでの確認（[13-2の検証記録](13-2-validation.md)）による。
