## 描画検証版に足した比較

`runRepaintCheck` へ次を追加しました。いずれも差分描画の結果と、直後に全面再描画した結果を
画素単位で突き合わせます。パネルを要素にしなかった設計が成り立っているかは、この比較が直接の検査です。
背景の塗り忘れや箱のずれは黒い抜けとして不一致に出ます。

- リセット済み、計測中、停止中 × ラップ0〜3件（8通り＋1）
- 1/100秒だけを25msずつ12フレーム進めたもの（時分秒とボタンが再描画されないことの確認を兼ねる）
- 桁上がりと表示上限（0、0.99秒手前、59.99秒、1時間手前、99:59:59.99、上限超過）
- ストップウォッチ表示中のトーストの出現と消滅
- 一覧へ戻ったときにストップウォッチの要素が消えること

あわせて、経過時間に使う `FreeSansBold24pt7b` の `0`〜`9` の文字幅が等しいことを検査します。
等幅でないと、固定した箱の中で値が数えるたびに横へ揺れます。

### 実機確認で見つかった不具合: 未収録グリフの検査がフォントを取り違える

| 項目 | 内容 |
|---|---|
| 症状 | 描画検証版の1回目が `checks=229 mismatches=1 result=FAIL`。落ちたのは `unsupported glyph fallback` で、ストップウォッチのピクセル比較ではない |
| 原因 | 作業5で足した「経過時間フォントの数字が等幅か」の検査が、測定のために `FreeSansBold24pt7b` を設定したまま抜けていた。直後の `fitText("外部アプリ😀")` がこのGFXフォントで測ったため、日本語をすべて未収録と判定して `?????` になった |
| 修正 | 検査ブロックの最後で `display.setFont(renderer.listFont())` に戻す |
| 再確認 | `checks=229 mismatches=0 result=PASS`（[20260922-2-render-check.log](20260922-2-render-check.log)） |

PC検証で出なかったのは、この検査が描画検証版にしかなく、M5GFXを必要とするためです。
ホスト側テストはM5GFXを含む層をビルドしないので、実機に載せるまで実行されません。
壊れたのは検査コードだけで、製品版の描画には影響しません。
