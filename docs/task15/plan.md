# 作業15: チュートリアル

作成日: 2026-10-10。状態: 計画。上位計画は[全体計画](../plan.md)。

## 1. 到達点と合意済み仕様

初回起動時に、日時の設定とホームへの戻り方を案内する。一覧には出さない内蔵の画面（チュートリアル）として作り、
ホストは「記録がなければチュートリアルを開く」ことだけを受け持つ。それ以外の流れはチュートリアルの中で閉じる。

### 1.1 流れ

1. 日時が未設定（`TimeService::valid()` が偽）なら、日時の設定を出す。設定済みなら2へ進む。
2. 「上端からのスワイプ、または A+B の長押しでホームへ戻る」ことを案内する画面を出す。
3. 案内の画面で実際にスワイプか A+B の長押しをしてホームへ戻ると、チュートリアルは完了する。

### 1.2 日時の設定

- 設定アプリの日時の編集と同じ見た目・操作とする（見出し「日時」、年・月・日・時・分の欄、A でフォーカス移動、B で+1）。
- ボタンも設定と同じ「保存」「キャンセル」とし、チュートリアルのために文言を分けない。保存できたら案内へ進む（「時刻を保存しました」のトーストは今どおり出す）。
  日付が不正なときと書き込みに失敗したときは、今どおりトーストを出してその場に残る。
- 「キャンセル」は、日時を未設定のまま案内へ進む。

### 1.3 完了と未完了

- 完了とするのは、案内の画面からホームへ戻ったときだけ。完了したら記録を書き、次の起動からはチュートリアルを出さない。
- 次の場合は未完了とし、次の起動でもう一度チュートリアルを最初から出す。日時が設定済みなら、日時の設定は飛ばす。
  - 日時の設定の途中でホームへ戻った（誤ってタッチして完了してしまうことを避ける）。
  - タイマーの通知などの注意の要求で、ほかの画面が前に出た（初回起動ではまず起きない）。
  - 完了の記録を書けなかった。
- 消灯しても、チュートリアルの画面はそのまま残る（ほかの画面と同じ）。

### 1.4 初回の判定

- `launcher` 名前空間に専用の記録（キー `tutorial`）がなければ、起動時にチュートリアルを開く。
- 新しいキーなので、既存の機器もこの版へ更新した後に一度だけチュートリアルが出る（NVS が残っていても記録はまだない）。
- 描画検証版は記録を読み書きしないので、チュートリアルを出さない。

## 2. この計画で採用する実装上の初期方針

ここは未指定の部分を補う初期方針である。寸法は466角の画面での値。寸法・文言は実機で調整してよい。

### 2.1 置き場所と責任

- `features/tutorial/` に `TutorialScreen`、`TutorialModel`、`TutorialLayout`、`TutorialLayer` を置く。
  `TutorialScreen` は1つの画面で、段階（日時・案内）を内部に持つ。画面をまたぐ遷移はないので、`ScreenManager` に流れの状態を持たせない。
- 日時の編集は、設定から切り出した共通の部品（2.2）を `TutorialScreen` が持つ。設定画面の状態には触れない。
- `LaunchRegistry`・アイコン・一覧の色は追加しない。`ScreenId::Tutorial` と描画の接続（`FrameModel`・`FrameComposer`・`HostRenderer`）は、ほかの画面と同じく必要である。

### 2.2 日時の編集を部品にする

今は `SettingsScreen` と `SettingsLayer` の中に、編集画面（日時・明るさ・消灯・情報）の入力と描画がまとまっている。これを部品に分ける。

- 入力: `SettingsEditor`（`features/settings/`）。表示（`SettingsView`）・フォーカス・欄の値・押し続け（`HoldRepeat`）を持ち、
  イベントを受けて「値が変わった」「ボタン i が押された」「動作 i が押された」を返す。保存や戻り先は持ち主が決める。
  `SettingsScreen` は日時・明るさ・消灯・情報の編集にこれを使い、今の `confirm()` の保存と戻り先を受け持つ。
- 日時の初期値（今の時刻、未設定なら `MinYear` の1月1日0:00）と保存（`TimeService::save()` の結果をトーストの文言にする）は、関数にして両方から使う。
- 描画: `SettingsLayer` の編集の要素（見出し・欄・区切り・情報の行・動作・ボタン）の組み立てと描画を、`SettingsEditorView` に移す。
  `SettingsLayer` はリスト（トップ・文字盤の選択）と `SettingsEditorView` を持つ。`TutorialLayer` も `SettingsEditorView` を持つ。
  ボタンの文言は今の設定と同じで、呼び出し側から変えられるようにはしない。
- 設定の見た目と操作は変えない。既存の設定のテストと、`RenderDiagnostics` の設定の画素比較がそのまま通ることを切り出しの完了条件にする。

### 2.3 ホームへ戻ったことを画面へ伝える

- `Screen` に `virtual void wentHome() {}` を足す。A+B かスワイプでホームへ戻るとき、`ScreenManager::goHome()` が表示中の画面に対して、`exit()` より前に呼ぶ。
  注意の要求（`present()`）・画面自身の退場では呼ばない。既存の画面は何もしない。
- `TutorialScreen::wentHome()` は、案内の段階のときだけ完了の記録を書く。

### 2.4 記録

- `storage/TutorialRecord`（`TimerPreferences` と同じ形）。キー `tutorial`、`[0] format 1`。中身は「完了した」ことだけで、ほかの値は持たない。
- `load()` が `Missing` を返したときだけチュートリアルを出す。未知の形式・読めないときは出さない（壊れた記録で毎回出るのを避ける）。
- 完了したときに1回だけ書く。失敗はログに出すだけで、トーストは出さない（次の起動でもう一度出る）。
- `tutorial` を `reservedRecordKey()` に加え、文字盤から使えないようにする。

### 2.5 ホストの接続

- `HostApplication` が `TutorialRecord` を所有し、`bindRecords()` で読む。
- 起動時、Runtime を始めた後に、記録がなければ `ScreenManager::present(ScreenId::Tutorial)` で開く。`present()` が受け付ける画面に `Tutorial` を足す。
- `ScreenManager` は `TutorialScreen` を所有し、`leaveAll()` で `exit()` し、モデルを合成する。`TimeService` と記録は `bind` で渡す。
- `TutorialScreen::enter()` は、`TimeService` が渡されていて時刻が未設定なら日時の段階から、そうでなければ案内の段階から始める。

### 2.6 案内の画面

- 黒背景に、見出しと本文を中央にそろえて置く。操作の対象は置かない（タップ・A・B 単独は何もしない）。
- 上端の帯（y ≤ 40px）の中央に、下向きの山形の印を描いて、スワイプを始める場所を示す。描画だけで、ヒット判定は持たない。
- 文言は次のとおり（日本語版・英語版）。行の分け方は実機で調整する。

  | 要素 | 日本語 | 英語 |
  |---|---|---|
  | 見出し | ホームへの戻り方 | Going home |
  | 本文1行目 | 画面の上端から下へ | Swipe down from |
  | 本文2行目 | スワイプするか | the top edge, |
  | 本文3行目 | A+B を長押しします | or hold A+B. |

- 日時の段階と案内の段階の切り替えは全面再描画にする（設定のリストと編集の切り替えと同じ）。

### 2.7 フォント

2.6の文言のうち、次の文字は今の `src/` に現れず、埋め込みフォントにない: ホ ム ワ へ か ら す 方 画 面 上 端 下 押（文言を調整して増えた分も加わる）。
`tools/build_font.py` で作り直す。TrueType フォントはユーザーに用意してもらう。

## 3. 確認の経緯

2026-10-10に次のとおり確認し、1章へ反映した。

1. 初回起動時に、日時が未設定なら日時の設定、次にホームへの戻り方の案内を出し、実際にホームへ戻るとチュートリアルを終える。
2. 一覧に出ない内蔵の機能としてまとめ、ホストは記録がないときに立ち上げることだけを受け持つ。
3. 日時の設定の途中でホームへ戻ったら未完了とする（誤ってタッチして完了することを避ける）。
4. 日時の設定を取り消したら、未設定のまま案内へ進めてよい。
5. 日時の設定には「日時」の見出しを出す（設定の日時の編集にはすでにある）。
6. 案内の文言は計画で案を出す（2.6）。促し（「やってみましょう」）は一旦入れず、必要なら最後に足す。
7. 日時の設定のボタンは設定と同じ「保存」「キャンセル」のままとし、チュートリアルのために場合分けしない。
8. チュートリアル中に注意の要求でほかの画面が出たら、そこで打ち切り、次の起動で出し直す。

## 6. 検証と完了条件

### ホスト検証

- 起動: 記録がないときだけチュートリアルが開くこと。記録があるとき・未知の形式・読めないとき・記録が渡されていないときは開かないこと。
- 段階: 時刻が未設定なら日時から、設定済みなら案内から始まること。保存できたら案内へ進むこと。不正な日付・書き込みの失敗ではその場に残ること。「キャンセル」で未設定のまま案内へ進むこと。
- 完了: 案内の段階でのスワイプと A+B で、ホームへ戻り、記録を1回書くこと。帯と幕が出ること。
- 未完了: 日時の段階でのスワイプ・A+B ではホームへ戻るが、記録を書かないこと。`present()` で打ち切られたときも書かないこと。書き込みの失敗で何も出さないこと。
- `wentHome()`: ホームのときだけ、`exit()` より前に呼ばれること。画面自身の退場・`present()` では呼ばれないこと。
- 操作: 案内の段階で、タップ・A・B 単独が何もしないこと。上端の帯にヒット判定がないこと（`home_gesture_tests` の走査に加える）。
- 保存キー: `tutorial` が文字盤の保存キーとして拒否されること。
- 設定: 切り出しの前後で、既存の設定のテストがそのまま通ること。

### 描画・実機検証

- 案内の段階、日時の段階（見出しとボタンが設定と同じであること）の全面描画との画素一致。段階の切り替え、トーストが重なったとき。
- 設定の既存の画素比較が切り出しの前後で変わらないこと。
- 日本語版・英語版の文言が画面に収まり、収録外の文字（`?`）がないこと。
- 実機で、初回起動から完了までと、未完了での出し直しを確かめる。
- 通常版・英語版・描画検証版のビルド、`verify_build.py`、既存の回帰テスト。

## 7. 範囲外

- 完了した後に、時刻が未設定になった（RTC の電池切れなど）ときに日時の設定を出すこと。
- 設定からチュートリアルをもう一度見る入口。
- ホームへの戻り方以外の操作（アプリ一覧の開き方など）の案内。
