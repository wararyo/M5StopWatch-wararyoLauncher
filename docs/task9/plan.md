# 作業9: UI設計の整理とリスト共通化

作成日: 2026-09-23。状態: 2026-09-26に9-5まで完了。
基準確認の結果と残項目は[改修前の基準確認](baseline.md)を参照。

[全体計画](../plan.md)の作業9の詳細を定義する。

## 1. 目的と合意事項

初版機能が揃った段階で、機能を追加・変更するときの影響範囲を小さくする。
共通描画基盤と機能固有のUIを分離し、アプリ一覧と設定トップメニューを同じリスト部品で実装する。

- 設定トップメニューの見た目・スクロール挙動は、アプリ一覧へ寄せて変更してよい。
- 日時・輝度・消灯時間の編集画面と情報画面は、今回リストへ統一しない。
- 計測サービスと画面の分離、単一UIタスク、全レイヤー共通の差分描画を維持する。
- 共通化だけで高速化したとはみなさない。両リストで最適化を共有できる構造を作り、効果は実測する。
- 汎用UIフレームワーク、追加アプリ、新しい文字盤、背景画像への対応は範囲外。
- 作業8の省電力化と並行する場合、待機・起床・PM設定を巻き戻さず、性能比較の条件を揃える。

作業7で残った一覧スクロールの30fps超未達は引き継ぐ。設計改善の完了と性能目標の達成は別々に記録し、
未達を共通化の完了によって合格扱いにしない。過去の測定記録は上書きしない。

## 2. 現状の課題

| 現状 | 改修方針 |
|---|---|
| `Renderer` が一覧の配置・文字整形・配色・描画とトーストを持つ | 機能レイヤーと共通リスト、トーストへ状態ごと移す |
| `apps/` と `ui/` に同一機能の操作・モデル・描画が分散 | 機能別フォルダにまとめ、共通基盤だけを `ui/` に置く |
| `ScreenModel` が全画面の表示情報と電源設定を持つ | 機能別モデルと実効設定に分ける |
| `WatchFace` や各レイヤーが全体モデルを受け取る | 必要なモデルと表示領域だけを受け取る |
| `ScreenManager` がホーム・一覧のジェスチャーと補間まで持つ | `LauncherController` と共通リスト操作へ移す |
| 設定メニューが一覧の配置関数を借りる一方、描画と入力は別実装 | 配置・ヒットテスト・描画・操作を共通部品へ集約 |
| 件数5や配列位置と表示上の意味が各所に埋め込まれている | 件数を入力にし、行の意味は安定IDで扱う |
| 背景復元と全面再描画の条件が個別実装の前提になっている | 共通の描画契約として明文化・検証する |

## 3. 目標構成と依存関係

9-4とレビュー後の命名整理で次の構成になった（[9-4の検証記録](9-4-validation.md)、[命名整理](naming-cleanup.md)）。

```text
src/
  core/                    # TimeUs（入力や描画に依存しない共通型）
  host/                    # HostApplication（構成）、HostRuntime、ScreenManager、Screen契約、
                           # FrameModel・FrameComposer、HostRenderer、RenderDiagnostics（診断アダプター）
  features/
    home/                  # HomeLayer（文字盤の登録・選択・寿命・期限）、WatchFace契約、HomeModel、HomeDataSource
      faces/               # DigitalWatchFace
    launcher/              # LauncherController、AppListLayer・Layout・Model・Rows、AppIcons、icons/
    stopwatch/             # Screen、Layer、Model、Layout、表示書式
    settings/              # Screen、Layer、Model、Menu、編集画面のLayout
    external/              # Screen、Layer、Model、Layout
  ui/
    list/                  # ListView、ListLayout、ListModel、ListController
    rendering/             # Renderer（RenderLayer・FrameOverlay）、FramePlan・Element、Geometry・Viewport・Scale
    graphics/              # Gfx、IconBitmap、fitText、VLWフォントとfonts/
    overlays/              # ToastLayer、StatsOverlay
  services/                # StopwatchService、TimeService等、画面の寿命から独立
  input/、hal/、storage/、power/、multifirm/
```

| 所有者 | 責務 |
|---|---|
| HostApplication | サービス（StopwatchService）・RuntimeSettings・終了処理・ScreenManager・HostRuntimeの寿命と参照の注入。終了処理をSlotServiceへ登録 |
| HostRuntime | 入力・電源・期限・スロット結果・描画の実行時期。ScreenManagerを借りて駆動し、状態を所有しない |
| ScreenManager | 現在画面、入退場、ホームの優先処理、起動先への振り分け、通知の寿命、FrameModelの合成、画面の要求（統計表示）の適用 |
| LauncherController | ホーム↔一覧の遷移、ジェスチャーの所有者決定、ランチャー専用ListController。起動先を返すだけで画面を開かない |
| HomeLayer | 文字盤の登録・選択・begin/end・キャッシュ・次回更新期限、切替時の全面再描画要求 |
| HostRenderer | RenderPortを実装。フレームを各レイヤーの入力へ分配し、描画順・画面切替の全面再描画・統計チップ・計測の記録を決める |
| Renderer | FramePlanの実行、全消去、順序付きpaint、転送前オーバーレイ、転送。具体的な画面・アプリID・診断を知らない |

機能は共通UIを利用する。共通リスト・描画基盤は `LaunchRegistry`、具体的な画面、NVS、OTAに依存しない。
描画と入力が使う配置計算は同じものを使い、配置の共有のために全体モデルを組み立て直す実装をなくす。
フォント等の共有資産は初期化時に渡し、リストからアプリ固有の資産表を参照しない。

`Renderer` はフレームの実行に集中する。機能レイヤーの所有と描画順の組み立ては `host/` の描画構成側（HostRenderer）が担当し、
`Renderer` には順序付けた描画対象（`RenderLayer` の固定長配列）を渡す。固定容量・静的な組み立てを基本とし、毎フレームの動的確保は導入しない。

## 4. 共通リスト

### 4.1 責務と入力

| 部品 | 責務 |
|---|---|
| `ListView` | 行の描画計画・描画、文字整形、キャッシュ、画面外の除外 |
| `ListLayout` | 円形に沿う配置、行矩形、クリップ、ヒットテスト |
| `ListState` | 選択、スクロール、操作・アニメーション中の状態 |
| `ListController` | Aによる選択移動、タップ・決定、ドラッグ・慣性、選択行の可視化、次回更新期限 |
| 各画面 | 行データの生成、行IDを受けた処理、画面固有の遷移 |

行データには安定ID、表示名、任意のアイコン、表示色等の最小限の見た目、操作可否を持たせる。
項目数と表示領域は入力とし、固定5件への依存を除く。空リスト、1件、容量上限も扱う。
表示名の借用は少なくとも当該フレームの終了まで有効とし、キャッシュに残す文字列は部品自身で保持する。
リストの状態・Element履歴・キャッシュはインスタンスごとに所有し、アプリ一覧と設定で混在させない。

薄い表示と操作禁止は分ける。起動できない外部スロットも選択・決定して理由を表示する現行動作を維持するため、
「起動不可だからリスト行を決定不可にする」という変換はしない。

### 4.2 操作と画面との境界

- Aは次の項目へ進み、末尾から先頭へ循環する。Bとタップは行IDの決定結果を返す。
- ドラッグ後のタップ抑止、慣性の停止と再操作、選択行の可視化を両画面で共通化する。
- ホームから一覧への遷移と一覧先頭の下スワイプによるホーム復帰は `LauncherController` の責務。
  共通リストは端でのジェスチャーを通知できるようにし、画面遷移先を知らない。
- 設定トップでは端のドラッグでホームへ戻らない。「戻る」行とA+Bホームを維持する。
- 設定の保存・キャンセル後は元のメニュー行とスクロール位置へ戻る。
  設定へ新しく入場したときは先頭から始める。
- 全画面共通のA+Bホームの優先順位と、外部起動確定中の例外は維持する。

設定トップはアプリ一覧と同じ配置・行高・選択表示・スクロール方式を使う。
アイコンなしの行も扱い、設定用アイコンの新規制作は必須にしない。
編集画面のフィールド操作、保存、キャンセル、情報画面の統計表示有効化は既存仕様を維持する。

### 4.3 最適化とメモリ

文字の省略結果と文字画像の保持、アイコンの描画最適化は `ListView` 側へ集約する。
文字・フォント・倍率・利用可能幅等をキャッシュ更新条件にし、色を画像へ焼き込む場合は色も条件に含める。
スクロール位置だけの変更では省略文字列を作り直さない。
初期版は固定容量の表示行キャッシュを基本とし、全画面バッファを追加しない。
確保失敗時は直接描画へ退避し、文字やアイコンを表示不能にしない。
別の変更で最適化が先行導入されている場合は、その実装と検証結果を確認して共通部品へ移す。

## 5. モデル・実行・所有権の整理

機能別の表示モデルを各機能に置き、全体を束ねるフレームモデルは構成側だけで使う。
各レイヤーは必要なモデルと表示領域・オフセット・クリップのみを受け取る。
`WatchFace` に設定・外部アプリ・一覧の状態を渡さず、時刻・電池情報と描画条件に絞る。
契約は `begin(Gfx&, disableCache)`・`end()`・`plan(FramePlan&, Gfx&, const DrawRegion&, const WatchData&)`・`paint`・`nextUpdate(now, WatchData)`。
文字盤の登録・選択・キャッシュ寿命はホーム側（HomeLayer）へ移し、更新期限と確保失敗時の退避を維持する。
時計の描画領域と可視性はFrameComposerが遷移率と現在画面から一か所で導出し、描画とRuntimeの期限が同じ判断を使う。

輝度・消灯時間は描画モデルから分離した実効設定としてRuntimeへ渡す。
保存済み設定はSettingsStoreを正とし、輝度編集中だけプレビュー値を優先する。
キャンセル・ホーム・復帰時の適用も同じ経路で扱う。統計表示の有効状態はアプリ全体の実行時設定として扱う。

`ScreenManager` は現在画面、入退場、ホームの優先処理、起動先への振り分けに集中する。
共通リストのアニメーション期限と活動状態は各画面からRuntime・PowerManagerへ伝え、
設定スクロール中も更新が継続し、静止・消灯中は不要な描画期限で起床しないようにする。

StopwatchServiceはアプリ全体の寿命で所有して画面へ注入する。
外部起動確定時の停止はアプリ側の終了処理へ移し、単なる画面退場では停止しない。
起動中表示を描画してから起動APIを呼ぶ順序と、確定前のホームによる中断を維持する。
`TimeUs` は入力ヘッダーから共通型へ移し、計測状態と表示用書式・更新周期の依存も分離する。

## 6. 描画契約

1. 全描画対象が同じフレームの不変データを使って、一つのFramePlanへ登録する。
2. 全planの完了後に重なりを解決し、必要な消去をすべて済ませてから背面順にpaintする。
3. 消える行・レイヤーの旧領域も消去する。画面切替時に全面再描画と履歴の無効化を行う経路を明示する。
4. 背景の復元主体を明示する。現行の黒背景を基本とし、ストップウォッチの固定領域は各要素が背景色まで塗り直す。
5. トーストの表示・消去等、現行実装が全面再描画へ依存する条件を維持する。
   StatsOverlayの最前面描画と独自の領域復元も契約に含める。
6. FramePlan容量超過時は全対象の全面再描画へ退避し、登録失敗した要素も欠落させない。

レイヤーごとに独立して消去・転送する方式には変更しない。
背景画像や一般的な半透明合成を今回の整理に合わせて追加しない。

## 8. 検証と完了条件

### ホストでの検証

既存の `tools/test_runtime.py` を継続使用する。共通リストについては空・1件・5件以外の件数、
末尾からの循環、ドラッグ後の誤決定防止、慣性停止、描画矩形とヒットテストの一致、期限の解除を検証する。
設定のメニュー復帰位置、ホーム時の編集破棄、プレビューの復元、外部スロットの理由表示を回帰確認する。

### 実機での検証

- 両リストの差分描画と全面描画を同じモデルで比較する。設定の新しい見た目は新しい基準で評価する。
- 長い名前、日本語、アイコンなし、薄い表示、遷移中、非表示化、トーストの出現・消失を確認する。
- キャッシュの無効化・確保失敗・再入場、FramePlan容量超過でも描画が欠落しないことを確認する。
- CPU/DFS設定、診断表示、USB条件を揃え、両リストの描画時間、実fps、フレーム間隔、入力遅延と
  内部RAM/PSRAMの空き・最大連続領域を比較する。両画面を繰り返し往復してメモリが減り続けないことを確認する。
- 静止中の描画停止、消灯・復帰、計測中のホーム・画面切替、外部起動の順序を確認する。
