# 作業5：ストップウォッチ

## 現在の操作

アプリ一覧の先頭「ストップウォッチ」を決定すると開きます。画面には丸いボタンが左右に2つ並び、
**左がAボタン、右がBボタン**に対応します。同じボタンを指でタップしても同じことが起きます。
この画面だけは「Aが次へ、Bが決定」に従いません（[全体計画](../plan.md) 5.1・5.3節）。

| 状態 | 左＝A | 右＝B |
|---|---|---|
| リセット済み | `LAP`（押しても何も起きません） | `START` |
| 計測中 | `LAP` | `STOP` |
| 停止中 | `RESET` | `START` |

- 経過時間は `HH:MM:SS.cc` で、計測中は25ms周期（40Hz）で進みます。
- ラップは計測中だけ記録します。新しいものが上に並び、画面に収まる最新3件を表示します。
  ラップ番号は通算で振るので、4件目以降を取ると `LAP 4`、`LAP 5` と続きます。
- **一覧へ戻るボタンはありません**。A+Bを600ms保持するホームで時計へ戻ります。
- ホーム・画面の退場・消灯では計測が続きます。止まるのは `STOP` を押したときと、
  外部アプリの起動が確定したときだけです。
- 外部アプリの起動は確認画面を挟まないので、**計測中でも黙って計測を終了**します
  （[全体計画](../plan.md) 1.1・8.2節）。起動に失敗したときは計測が続きます。
- 表示は `99:59:59.99` で頭打ちになります。内部の値はそのまま進み続けます。
- 計測値は電源断・再起動・外部アプリへの切り替えをまたいで復元しません。

見た目は [M5StopWatch-UserDemo](../../M5StopWatch-UserDemo/main/apps/app_stopwatch) の
ストップウォッチに合わせました。押下時にボタンが沈むアニメーションと、上端の弧に沿う
現在時刻（UserDemoの `ArcTopClock`）は入れていません。理由は[作業5の計画](plan.md)にあります。

## 構成

| 場所 | 責務 |
|---|---|
| `services/Stopwatch.h` | 状態・ラップ行数・表示上限・更新周期・表示モデルと `formatStopwatch`。M5GFXにもHALにも依存しない |
| `services/StopwatchService.*` | 計測そのもの。与えられた単調時刻だけを使い、壁時計・描画周期・保存を持たない |
| `apps/StopwatchScreen.*` | 入力の割り当てとサービスのサンプリング。計測状態を自分で持たない |
| `ui/StopwatchLayout.h` | 矩形と当たり判定。描画とヒットテストが同じ値を読む |
| `ui/StopwatchLayer.*` | plan / paint。背景としてのパネルと、箱を固定した7要素 |
| `app/ScreenManager.*` | サービスの所有、行の分岐、表示更新期限の駆動、`BootShutdown` の実装 |

計測は `StopwatchService` が持ち、画面は持ちません。そのため画面を離れてもホームへ戻っても
消灯しても計測が続きます。画面は `enter` / `handle` / `tick` のたびに経過時間を読み取って
保持し、`model()` はその保持値を返すだけです。`ScreenManager::model()` が時刻を受け取らない
ためでもあり、同じフレームの中で表示データが動かないという
[全体計画](../plan.md) 4.1節の規約に沿うためでもあります。

### パネルは要素ではなく背景です

`FramePlan` は矩形が交差する要素へ再描画を伝播します。466×330のパネルを要素として登録すると、
1/100秒が変わるたびにパネルが塗り直され、そこからラップ行・仕切り・ボタンへ連鎖して、
実質的な全面描画が40Hzで走ってしまいます。

そこで**パネルと仕切りは要素にせず、全面再描画のときだけ描く背景**にしました。
消去処理は登録要素の旧矩形を黒で塗るだけなので、代わりに次の2つを守っています。

- ストップウォッチの要素はすべて**箱が固定**です。値が変わっても矩形は動きません。
- 各要素は**自分の箱全体をパネル色で塗ってから**中身を描きます。黒い消去を同じフレームで覆います。

パネルに穴を開けうるのはトーストだけですが、トーストの出入りは `Renderer::draw` が
全面再描画にするので安全です。画面の切り替えも同じです。
この決まりが守れているかどうかは、描画検証版のピクセル比較がそのまま検査します。
差分描画の結果と全面描画の結果を突き合わせるので、塗り忘れた背景は不一致として出ます。

要素は 経過時間の時分秒1・1/100秒1・ボタン2・ラップ行3 の**7**です。時分秒と1/100秒を
分けているので、40Hzで塗り直すのは1/100秒の小さい矩形だけで済みます。
同時最大は 時計5＋一覧行5＋トースト1＋max(設定11, ストップウォッチ7, 外部6) = **22**（容量32）で、
作業6から増えていません。

### 表示更新期限を画面から出せるようにしました

`AppRuntime` 自身の表示期限は時計が見えているときしか設定されません。アプリ画面が時計を
覆っている間は `INT64_MAX` なので、画面が自分の周期で描き直してもらう手段がありませんでした。

`AppScreen` に `tick(TimeUs)`（既定は何もせず偽を返す）を足し、`ScreenManager::update()` が
`nextUpdate()` の期限を過ぎていたら呼ぶようにしました。設定画面と外部アプリ画面は既定のままです。
`StopwatchScreen::tick()` は経過時間を読み直して期限を25ms進め、真を返します。
計測していないときの期限は `INT64_MAX` なので、停止中とリセット済みの画面は1フレームも描きません。
消灯中は `AppRuntime` が `update()` も `nextUpdate()` も見ないので、期限ごと止まります。

あわせて `AppScreen::enter()` が時刻を受け取るようにしました。開いた最初のフレームから
正しい経過時間を出すためで、設定画面と外部アプリ画面は引数を使いません。

### 外部アプリ起動との接続（作業6の残り2項目）

`bootSlot` の shutdown コールバックは、起動先を設定したあと再起動する前に、**呼び出した
タスク**（UIタスク）で実行されます。API が失敗したときは呼ばれません。この性質がそのまま
[全体計画](../plan.md) 8.2節の4と5になります。

`SlotService` に `BootShutdown` と `bindShutdown()` を足し、`ScreenManager` が実装して
`bindSlots()` で自分を登録します。`onBootCommitted()` は計測を止めるだけです。
`FakeSlotService` も成功時にだけフックを呼ぶので、成功と失敗の両方をPCで検証できます。

### フォント

追加した文言は `LAP` / `START` / `STOP` / `RESET` / `LAP n` / `-.-` ですべてASCIIです。
**埋め込みフォントの部分集合は変わらないので、`tools/build_font.py` の再実行も
`src/ui/fonts/GenShinGothicMedium28.vlw` の再コミットも不要**です（337グリフ・168,570 bytes のまま）。
`RenderDiagnostics.cpp` の `covered()` の文言も変えていません。
一覧の行でストップウォッチが開けなかったときに出る「準備中」は、フォールバックとして残しました。

経過時間は `FreeSansBold24pt7b` を、`textWidth("00:00:00")` から箱に合わせた倍率で描きます。
決め打ちの倍率を置いていないので、表示できる最大値が必ず収まります。
数字が等幅でないと固定した箱の中で値が横に揺れるため、描画検証版に
`0`〜`9` の文字幅が等しいことの検査を足しました。

## PC検証とビルド

```powershell
python tools/build_icons.py --check
python tools/build_font.py --source <GenShinGothic-Medium.ttf> --check
python tools/test_runtime.py
python -m unittest discover -s tests -v
pio run -e m5stopwatch
python tools/verify_build.py
pio run -e m5stopwatch-render-check
python tools/verify_build.py --environment m5stopwatch-render-check
pio run -e m5stopwatch-diagnostics
python tools/verify_build.py --environment m5stopwatch-diagnostics
```

`tools/test_runtime.py` は6スイートです。`stopwatch_tests` が計測・ラップ・書式・画面の入力・
表示期限・消灯中の停止、`multifirm_tests` が起動失敗時の計測継続と起動成功時の計測終了を見ます。
残りの4スイートは作業2〜4から変更していません。

## 実機確認手順

導入は[作業1のinstall-host手順](../task1/product-build.md)に従います。通常uploadは使いません。

1. 通常版で起動し、一覧からストップウォッチを開きます。UserDemoと見比べて、ボタン・パネル・
   経過時間・ラップ欄の配置と色、文字サイズを確認します。
2. 物理A/Bと画面タップの両方で、開始・停止・再開・リセット・ラップを操作します。
   リセット済みの状態で左ボタンを押しても何も起きないことを確認します。
3. ラップを4回以上取り、新しい3件だけが上から並び、番号が通算で増えることを確認します。
   リセットでラップ欄が `-.-` に戻ることを確認します。
4. 計測中に1/100秒が滑らかに進み、他の要素がちらつかないこと、パネルに黒い抜けが出ないことを
   確認します。
5. ホーム（A+B）で時計へ戻り、開き直して計測が続いていることを確認します。
6. 計測中に消灯させ、復帰後に消灯していた分を含む経過時間が出ることを確認します。
   消灯中に描画が止まっていることをログで確認します。
7. 設定から日時を前後に変更し、計測値が飛ばないことを確認します。
8. 1時間以上の長時間計測と、表示上限付近の値を確認します。
9. 計測中に外部アプリ（Readyのスロット）を起動し、ゲストから戻ったあと計測が終了していることを
   確認します。空き・破損スロットで起動が失敗したときは計測が続くことを確認します。
10. 描画検証版で `result=PASS` / `mismatches=0` を確認します。
11. 過負荷診断版で60秒以上動かし、WDTと描画破綻がないことを確認してから通常版へ戻します。

結果は[作業5の検証記録](task5-validation.md)へ追記します。
