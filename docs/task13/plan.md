見た目の基準は[歩数計画面](../Images/Pedometer/Steps.png)（寸法は[SVG](../Images/Pedometer/Steps.svg)）。

## 1. 到達点と合意済み仕様

一覧のタイマーの次に「歩数計」を置く。BMI270の歩数計で数え、午前4時から翌日の午前4時までを1日として、今日の歩数を表示する。
10,000歩以上になったら、文字盤のバックグラウンド情報にも出す。

### 1.1 数え方と1日

- BMI270の機能エンジンの歩数計で数える。ESP32が眠っていてもIMUが数え続ける。
- 1日はJSTの午前4時から翌日の午前4時まで。画面と文字盤に出すのは「今日」の歩数だけ。
- 4時になったら0から数え直す。消灯中でも4時に起きて区切る（点灯も描画もしない）。
- 時刻が未設定の間は日を区切らずに数え続ける。時刻を設定したら、それまでの歩数をその日に含める。
- 日時を手で変えて「日」が変わったら、その時点から新しい日として0から数える。

### 1.2 再起動・外部アプリ・電源OFF

起動のたびに`beginImuWake()`がBMI270をソフトリセットするので、IMUのカウンタは0に戻る。外部アプリから戻るときもランチャーは再起動する。

- 今日の歩数を日の番号と一緒にNVSへ保存し、起動時に同じ日の記録なら引き継ぐ。
- 保存するのは、消灯したとき（前回の保存から変わっていれば）と、外部アプリの起動を確定したとき。
- 範囲外: 外部アプリの実行中と電源OFF中の歩数。電池切れや異常リセットで失われる、最後の保存より後の歩数。

### 1.3 歩数計画面

- 上から、歩くアイコン、「今日の歩数」、3桁区切りの歩数と単位「歩」、`OK`ボタンを並べる。
- `OK`のタップ、B短押し、A短押しのどれでも一覧へ戻る（`ScreenOutcome::leave`。外部アプリの詳細の「戻る」と同じ）。
  Aで移る先がないので、Aもタイマーの満了画面と同じくOKと同じ扱いにする。A+B長押しでホームへ戻るのは全画面共通のとおり。
- 表示中は1秒ごとに歩数を読み直し、変わったときだけ描き直す。
- IMUが使えないときも画面は開き、歩数を`--`と表示する。
- 英語版は「Steps today」と単位「steps」（数にかかわらず同じ）。

### 1.4 文字盤のバックグラウンド情報

- 今日の歩数が10,000歩以上のときだけ出す。
- 書式: 10,000〜99,999歩は0.1K単位に切り捨てて`10.0K`〜`99.9K`。100,000歩以上は1K単位に切り捨てて`100K`のようにする。英語版も同じ。
- アイコンは歩数計のアイコン。推奨色は一覧の円と同じ`#28B33D`。
- 登録順（表示の優先順位）は最後で、ストップウォッチ→タイマー→歩数計の順。文字盤に出せるのは最大2つなので、ストップウォッチとタイマーが両方動いている間は出ない。
- IMUが使えないときは出さない。

### 1.5 一覧

- タイマーの次に「歩数計」（英語版は`Pedometer`）を置く。
- 円の色は`#28B33D`（RGB565で`0x2d87`）、アイコンは白（`AppIconWhite`）。

### 1.6 範囲外

- 昨日以前の履歴、目標の設定、10,000歩に達したときの振動などの通知。10,000歩の閾値は固定。
- 1.2節に挙げた、外部アプリの実行中・電源OFF中・最後の保存より後の歩数。

## 2. この計画で採用する実装上の初期方針

ここは未指定の部分を補う初期方針である。寸法・頻度は実機で調整してよい。状態遷移や保存仕様を変えた場合は記録する。

### 2.1 BMI270の歩数計

- 歩数計は、手首のウェイク（[ImuWake.cpp](../../src/hal/ImuWake.cpp)）が読み込む機能エンジンのイメージに含まれている（Bosch BMI270_SensorAPIの既定`bmi270.c`と同一）。
  初期化の中で有効化ビットを立てるだけで済み、イメージを差し替える必要はない。
- Bosch APIでの位置: 有効化は機能ページ6のバイト3のbit4（`STEP_CNT_4`の上位バイト）。歩数は機能ページ0の`0x30`〜`0x33`（32bit、リトルエンディアン）。13-1で、実機から読み出して確かめる。
- ウォーターマークの割り込みは使わない。INT1は今どおり手首のウェイクだけにつなぎ、歩くたびにESP32を起こさない。
- advanced power save中は、書き込みの後に450µsの間隔が要る。初期化の最後に機能ページを0へ戻しておけば、読み取りは4バイトを読み出す1回で済み、書き込みは要らない。
  実行中に機能ページを切り替える処理はほかにない。
- 加速度計は手首のウェイクのため、すでに50Hzの低電力モードで動いている。追加の電力は小さい見込みだが、有効化の前後で消灯中の電流を比べる。
  （13-1で変更: 低電力モードでは歩数の出力がほとんど0で読めたため、加速度計を50Hzの性能モードにした。[13-1の検証記録](13-1-validation.md)）
- 歩数の調整値はイメージの既定値のまま使う。精度は13-5で測り、問題があれば調整を別に検討する。
- `Hal`に歩数を読む仮想関数を足す。IMUのない偽物は「読めない」を返す。

### 2.2 今日の歩数の求め方

- `PedometerService`（`services/`）が、今日の日の番号、起動前から引き継いだ歩数、今日の始まりのカウンタ値、最後に読んだカウンタ値を持つ。
  `HostApplication`が所有する。IMUからは、`TimeService`と同じくHALを借りて読む。
- 今日の歩数 = 引き継いだ歩数 +（最後に読んだカウンタ − 今日の始まりのカウンタ）。
- 区切りでは、その時のカウンタ値を今日の始まりにし、引き継いだ歩数を0にする。IMUのカウンタはリセットしない（機能ページへの書き込みを避ける）。
- 読んだカウンタが前回より小さければIMUがリセットされたとみなし、それまでの分を引き継いだ歩数へ移してから数え直す。
- 読み取りに失敗したら前の値を保つ。

### 2.3 日の区切りと時刻の合わせ直し

- 日の番号は「JSTの時刻から4時間引いた日付」とする。[CivilTime.h](../../src/services/CivilTime.h)と同じく純関数にし、境界をホストテストで確かめる。
- 4時の区切りは、システム時計から求めた時刻を単調時刻の期限に直し、消灯中も待つ（light sleepからの起床に使う）。
- 消灯中の単調時刻は大きく進むことがある。5f36ae6の測定では、20分眠ったタイマーで約7,500ppm進んだ。
  そのままでは、20時間前に決めた4時の期限が約9分早く来る。
  そこで`PedometerService`を[ClockFollower](../../src/services/ClockFollower.h)（5f36ae6）として登録し、区切りの10分前と1分前に、消灯したままRTCへ合わせ直してから期限を決め直す。
  タイマーの合わせ直しの最後の2段と同じで、7,500ppmでも区切りのずれは約0.5秒に収まる。
- 合わせ直しで分かる量（`clockCorrected()`）は使わない。日の区切りはシステム時計で決まるので、合わせ直した時計を読めば足りる。
- 毎stepシステム時計から日の番号を求め、今日と違えば新しい日にする。日時の手動設定と、未設定から設定したときもここで扱う。
  時刻が未設定（`TimeService::valid()`が偽）の間は区切らない。
- 区切りの時刻に読めなければ1秒後に読み直す。3回続けて失敗したら、最後に読んだ値で区切る。
- 許容する端の動き: 4時の直後に、点灯時の合わせ直しで時計が4時より前へ戻ると、前の日へ一度戻ってからもう一度区切る。
  その間の歩数は失われ得るが、区切りの直前に合わせ直しているので、その量は1秒未満である。

### 2.4 読み取りの頻度

| 状況 | 読み取り |
|---|---|
| 歩数計画面を表示中 | 1秒ごと（画面の`nextUpdate()`）。値が変わったときだけ描き直す |
| 時計が見えている | 時計を描くフレームで、情報を集める前に、最後の読み取りから30秒以上経っていれば読む。電池情報と同じく描画に相乗りし、歩数のために時計を起こさない。分表示の文字盤では最大で約1分遅れる |
| 消灯したとき | 1回読んで保存する（2.5節） |
| 消灯中 | 4時の区切りでだけ読む（区切りの前の合わせ直しでは読まない） |
| 外部アプリの起動確定 | 1回読んで保存する |

- 消灯中も期限を待つこと、消灯したときと時計を描く前に呼ばれることが要る。`AttentionSource`・`ClockFollower`と同じく`HostRuntime`への登録式の口にする。
  名前と形は13-2の詳細計画で決める。
- 文字盤の情報の`nextChangeAt`は持たない。いつ変わるかは読むまで分からず、変わったことは相乗りの読み取りで分かるため。

### 2.5 保存

- `launcher`名前空間に、版付きの専用レコード（キー`pedometer`）を置く。
  `[0]` 版1、`[1..4]` 日の番号（int32）、`[5..8]` 歩数（uint32）。どちらもリトルエンディアン。設定レコードの版は上げない。
- 消灯したときと外部アプリの起動確定時に、最後に保存できた値と違うときだけ書く。
- 4時の区切りでは書かない。残すのは今日の歩数だけなので、区切りの直後に書いても、再起動後に引き継ぐ値は変わらないため（3章）。
- 時刻が未設定の間は書かない（日の番号がない）。
- 起動時は、時刻が有効で記録の日の番号が今日のときだけ引き継ぐ。違う日・未知の版・不正値・時刻未設定のときは0から数え、次の保存で上書きする。
- 保存に失敗しても通知しない。次に書くかどうかは、メモリの値ではなく最後に保存できた値と比べて決める。
- `pedometer`を`reservedRecordKey()`に加え、文字盤の保存キーと衝突しないようにする。
- 書くのは値が変わった消灯のたびで、1日数百回でもNVS（64KB）の消耗は問題にならない見込み。13-5で1日の回数を記録する。

### 2.6 見た目

- 寸法は[Steps.svg](../Images/Pedometer/Steps.svg)の466角を基準にし、タイマーと同じく中心からの相対で実際の画面へ拡大縮小する。背景は黒。
- アイコン: 44×44（`x=211, y=17`）、白。
- 「今日の歩数」: 日本語フォント28px。中央にそろえ、字面は`y=145`〜`171`。
- 歩数: タイマーの数字グリフ（D-DIN-PRO Exp SemiBold 64px、`timerDigitGlyphs()`）に`,`を足して共用する。
  SVGの数字（`12,345`）は字高41px・幅180px。64pxのグリフは字高44〜46px、送り幅の合計が約181pxで、ほぼ合う。
- 単位「歩」（28px）は数字の右に約10px空けて置き、下端を数字の底（`y≈266`）にそろえる。数字と単位の組を中央にそろえる。
- `--`は同じグリフで描く（`-`は収録済み）。
- `OK`: 160×44（`x=153, y=360`）、角丸8、黄緑（`#C4F24F`）の地に黒の`OK`（`watchTextFont()` 28px）。ほかに対象がないので、常にこの表示にする。
- フォント:
  - 日本語の部分集合に`今`・`歩`・`数`がない（`日`・`の`・`計`はある）。`GenShinGothic-Medium.ttf`から作り直す。

## 3. 確認の経緯

2026-10-06〜07に次のとおり確認し、1章へ反映した。

1. 1日は午前4時から翌日の午前4時まで。
2. 再起動・外部アプリをまたぐ歩数は、今日の歩数をNVSへ保存して引き継ぐ。外部アプリの実行中と電源OFF中は数えない。
3. 4時の区切りのために、消灯中も1日1回起こしてよい。
4. 文字盤の情報の優先順位は最後。
5. 次の提案を了承: 操作（OK・A・Bで一覧へ）、読み取りの頻度、時刻が未設定のときと手動で変えたときの扱い、範囲外、英語の文言、IMUが使えないときの表示、寸法をSVGから取ること。
6. 一覧の円の色は`#28B33D`、前景は白。
7. 見た目の寸法は[Steps.svg](../Images/Pedometer/Steps.svg)。
8. タイマーのフォントは作業12で作り直し済みなので、歩数計の文字のためにもう一度作り直す。

計画にあたって、合意の時点から次の2点を変えた。

- 合意の時点では、4時の区切りでも保存するとしていた。残すのは今日の歩数だけなので、区切りで書いても再起動後に引き継ぐ値は変わらない。そのため書かないことにした（2.5節）。
- 合意の時点では、4時の区切りのずれを「消灯中のシステム時計の進み、1日最大30秒程度」と見積もっていた。
  5f36ae6の測定（約7,500ppm）では約9分早まり得るので、`ClockFollower`で区切りの前に合わせ直すことにした（2.3節）。

## 6. 検証と完了条件

### ホスト検証

- 日の番号: JSTの03:59:59と04:00:00、月末・年末・閏日。04:00:00ちょうどから求めた次の区切り。
- 今日の歩数: 始まりのカウンタを引くこと、カウンタが減ったとき（IMUのリセット）に引き継ぎへ移すこと、読み取りに失敗したら値を保つこと。
- 区切り:
  - 消灯したまま4時に起き、点灯も描画もしないこと。
  - 区切りの10分前と1分前に合わせ直しを求め、合わせ直した後に期限を決め直すこと。
  - 区切りの時刻に読めなかったときの読み直しと、3回失敗したときの扱い。
- 時刻: 日時の手動設定で日が進んだときと戻ったとき、未設定から設定したとき（歩数を保つ）、未設定の間は区切らないこと。
- 引き継ぎ: 同じ日の記録を引き継ぐこと。違う日・未知の版・不正値・時刻未設定では0から数えること。
- 保存:
  - 消灯したとき、値が変わっていれば1回書き、変わっていなければ書かないこと。外部アプリの起動確定で書くこと。4時の区切りでは書かないこと。
  - 失敗しても通知せず、次に書くかどうかを最後に保存できた値で決めること。
  - `pedometer`が文字盤の保存キーとして拒否されること。
- 読み取りの頻度:
  - 画面を表示している間だけ1秒の期限を持つこと。
  - 時計を描くフレームでだけ、30秒以上経っていれば読むこと。時計が隠れているとき・消灯中は読まないこと（区切りを除く）。
  - 歩数のために時計を起こさないこと。
- 書式: 9,999歩は出さない。10,000→`10.0K`、10,099→`10.0K`、10,999→`10.9K`、99,999→`99.9K`、100,000→`100K`、123,456→`123K`。
- 登録順: ストップウォッチとタイマーが両方動いている間、2つまでの文字盤には出ないこと。片方だけなら2番目に出ること。
- 画面: 入退場。OKのタップ・A・Bで一覧へ戻ること。A+Bでホームへ戻ること。IMUが使えないときの`--`。3桁区切り（日本語版・英語版）。

### 描画・実機検証

- 歩数計画面の全面描画との画素一致。0、`12,345`、`123,456`、`--`の各表示と、値が変わったときの部分描画を含める。一覧の行（色とアイコン）も確かめる。
- 文字盤の情報（`10.0K`）を各文字盤で表示したときの画素一致。
- 精度: 手で数えながら100歩を3回歩き、差を記録する。短い歩き（10歩程度）で数え始めが遅れるかも記録する。
- 区切り: 設定で03:50にし、消灯したまま4時をまたぐ。合わせ直しと区切りのログ、区切った後の歩数が0から始まることを確かめる。
- 引き継ぎ: 外部アプリを起動して戻ったとき、今日の歩数が保たれること。外部アプリの実行中に歩いた分は数えないこと。
- 電力: 歩数計を有効にする前後で、消灯中の平均電流を比べる。1日の保存回数を記録する。
- 手首のウェイク・タイマー・ストップウォッチの既存の動作に影響がないこと。
- 通常版・英語版・描画検証版のビルド、`verify_build.py`、既存の回帰テスト。
