# 12-2 検証記録: TimerServiceと通知の基盤

実施日: 2026-10-06。上位計画は[作業12の計画](plan.md)の2.1節・2.4節・2.5節。
段階の詳細計画（`plan-12-2.md`）は作らず、計画書をそのまま実装した。画面（入力・カウントダウン・満了）は12-3で行う。

同日、最初の実装で`HostRuntime`にタイマー専用の処理（満了の確定・通知・振動パターン）を直接入れていたのを見直した。
機能が装着者の注意を求める汎用の仕組み（`AttentionSource`）を設け、タイマーはその要求元の一つにした。コミットはamendで置き換えた。
以下は見直し後の内容。

## 1. 実装の要点

- `TimerService`（`src/services/`）: `Idle / Running / Paused / Ringing`。単調時刻だけで数える。
  - `start`はIdleから1秒〜`99:59:59`だけ。`pause`は満了後には効かない。`expire`は満了時刻（`now`ではない）から鳴らす。
  - `normalizeTimer(時,分,秒)`で繰り上げと上限（`01:75:60`→`02:16:00`、`99:99:99`→`99:59:59`）。
- `TimerVibration.h`（`src/features/timer/`）: 通知開始からの経過時間で強さと次の区切りを返す純関数。
  0〜10秒は弱（2秒ごとに200ms）、10〜20秒は中（200ms×2、2秒周期）、20〜60秒は強（400ms振動・200ms休止）。強さの値は暫定（弱140、中190、強255）。
- `TimerPreferences`（`src/storage/`）: キー`timer`、`[0]版1 [1..4]秒（LE）`。最後に保存できた値と違うときだけ書く。失敗してもRAMの値は保つ。
  `timer`を`reservedRecordKey()`へ追加した。
- `AttentionSource`（`src/host/`）: 要求元が「今の要求」（有効か、前に出す画面、点灯を保つ時刻、振動の強さ）を返す契約。
  `attended()`で開始時刻を受け取り、`nextAttention()`で次に尋ねてほしい時刻を返す。
- `TimerAttention`（`src/features/timer/`）: `TimerService`を見て要求を作る。尋ねられたときに満了を確定し、鳴っている間は要求する。
  開始から1分間は点灯を保ち、振動は開始からの経過時間でパターンに従う。`TimerService`は画面や振動を知らない。
- `HostRuntime`（汎用）
  - stepの最初、入力より前に全要求元へ尋ね、要求が始まったときだけ押下中の操作を捨て（`InputController::discardHeld()`）、
    消灯中なら点灯し、画面を`ScreenManager::present()`で前に出し、`attended()`を呼ぶ。外部起動の確定中は始めない。
  - 始まっている要求の点灯の保持と振動を毎step反映する（複数なら保持は遅い方、振動は強い方）。要求がなくなれば外れる。
    入力の後にも尋ねるので、入力による解除はその同じstepで反映される。
  - 要求元の`nextAttention()`を、消灯中も待機の期限にする。振動の書き込みに失敗したら50ms後に再試行する。
- `ScreenManager::present()`: 表示中の画面をホームと同じく退場させ、指定の画面を開く（現時点ではストップウォッチ・設定・時計）。
  ホームと共通の退場処理を`leaveAll()`にまとめた。
- `PowerManager::holdUntil()`: その時刻まで点灯を保ち、それを最後の操作として消灯時間を数える。
- `HostShutdown`: 外部起動の確定時にタイマーを止め、振動も止める。
- `M5Hal::setVibration()`: M5IOE1のPWM1デューティを書いて読み戻し、合わなければ3ms後に最大3回まで書き直す。
  M5IOE1はI2Cが1秒静かだと眠り、眠っている間のアクセスは失敗して起こすだけになるため。
- `HostApplication::bindRecords()`: 前回値のレコードを読み込む。描画検証版では呼ばない（文字盤のレコードと同じ扱い）。

## 2. ホスト検証

`python tools/test_runtime.py`: 新しい`timer_tests`を含む全9スイートが日本語・英語でPASS（見直し前は[ログ](20261006-12-2-host-2.log)、見直し後は[ログ](20261006-12-2-host-3.log)）。
[1回目](20261006-12-2-host-1.log)はテスト側の誤りで失敗した。点灯直後のフェードが16ms間隔で待機を終えることを見落とし、`wait()`の戻り時刻を振動の区切りと決めつけていた。

`timer_tests`の内容:

- 正規化: `01:75:60`、`00:00:99`、`99:99:99`、`99:59:59`、`00:00:00`、負の値。
- 計時: 0秒・上限超の開始拒否、二重の開始拒否、一時停止中に残りが減らないこと、再開、満了の直前・ちょうど、満了後の一時停止拒否、
  1回だけの満了、遅れて気づいても満了時刻から数えること、解除・リセット・取り消し。
- 日時の手動保存で残り時間と期限が変わらないこと。
- 振動パターン: 各段階の境界、60秒で打ち切り、区切りを順にたどって常に前へ進み、各振動が1秒未満で、60秒で終わること。
- 前回値: 未接続、記録なし、正規化後の保存、同じ値では書かない、失敗時にRAMの値を保ち最後に保存できた値と比べること、
  未知の版・範囲外・長さ違いで既定値になり書き換えないこと、文字盤から`timer`キーを使えないこと。
- Runtime: 電池駆動のlight sleep中も待機が満了時刻で終わる、点灯とlight sleepの禁止、振動の区切り、休止中も含め1分間点灯したまま、
  通知の終わりから30秒で消灯、鳴ったままでも通知を繰り返さないこと。
- 早めの解除で振動が止まり、解除した入力から30秒で消灯すること。
- 振動の書き込み失敗の再試行（通知中と、解除後の停止）。
- 満了と同じ周期のBのリリースで一覧の項目が起動しないこと、その後の新しい押下は効くこと。
  A+Bを満了をまたいで押し続けてもホームにならず、押し直せばホームになること。
- 外部起動: 確定に成功するとタイマーと振動が止まり、失敗すると鳴ったまま通知が続くこと。`HostShutdown`単体でも計時中のタイマーを止めること。
- 注意の要求の契約（テスト用の要求元で）: 消灯中も`nextAttention()`まで待つこと、開始時に押下中のBのリリースが捨てられ、点灯し、
  画面が前に出て、`attended()`に開始時刻が渡ること、開始は1回だけで振動と点灯の保持が今の要求に従うこと、
  要求をやめると最後の入力から消灯時間を数えること、再び要求すれば再び始まること、2つの要求元で振動は強い方・保持は遅い方、登録の上限。
- `present()`: 一覧からストップウォッチを前に出すと一覧は時計の位置へ戻ること、一覧・外部詳細は前に出せず何も変えないこと、
  使えない設定は拒否されること、時計を前に出してもホーム操作としては数えないこと。
