# 作業3：描画基盤・時計・アプリ一覧

## 現在の操作

通常版は時計を起点にします。作業4のTimeService接続前なので、時刻は `--:--`、
日付欄は `SET TIME`、電池は `--%` と表示します。RTCやNVSは読み書きしません。

- 時計のAPPSタップ、A/B短押し、上スワイプで一覧を開く。
- 一覧はストップウォッチ、設定、外部アプリ1〜3。Aで選択を循環し、選択行が中央へ移動する。
- Bまたは行タップで「準備中」を1.4秒表示する。全項目が起動不可で、ゲスト走査はまだ行わない。
  行にはアプリ名だけを28pxで表示し、起動不可の理由文は並べない。
- 一覧を上下にドラッグし、解放後に近い行へ位置補正する。先頭から下スワイプすると時計へ戻る。
- 先頭以外で始めたスクロールは、先頭に達しても同じ接触中にはホーム操作へ変わらない。
- A+B連続600msは補間・ドラッグ・通知をキャンセルして時計へ戻る。
- 消灯・タッチ消費・ボタン復帰は作業2の規約を維持する。

補間は180ms、次フレームの目標期限は16ms。時計のスワイプ確定は短辺比50/468を超えたとき。
InputControllerのドラッグ判定（短辺/50）とは別のしきい値です。
補間中のA/Bは最新位置から処理し、ドラッグ中はホームを除くボタン操作を抑止します。
慣性スクロールは実装していません。

## 構成

| 場所 | 責務 |
|---|---|
| `app/ScreenManager.*` | 意味イベント、選択、ドラッグモード、経過時間による補間、通知期限 |
| `ui/DisplayModel.h` | M5GFXから独立した表示スナップショット、RenderPort、DisplayDataSource |
| `app/AppRuntime.*` | UIタスク上で入力→状態更新→データ取得→描画→待機を接続 |
| `ui/ListLayout.h` | 円形の安全領域、行配置、APPSと行の当たり判定 |
| `ui/Element.*` | 固定容量の差分計画。矩形と重なりの解決はPCでもテスト可能 |
| `ui/WatchFace.h`、`DigitalWatchFace.*` | 安定ID、初期化・解放、plan/paint、次回更新期限、時刻文字キャッシュ |
| `ui/Renderer.*` | 全レイヤー計画、消去、背面から描画、M5GFXへの直接描画 |
| `ui/Text.*` | UTF-8の幅による省略、未収録文字の `?` 置換 |
| `ui/RenderDiagnostics.*` | 描画検証版のみのデータ注入、ピクセル比較、性能集計 |
| `hal/M5Hal.*` | 入力・単調時刻・USB・表示電源・待機。画面内容は持たない |

時計はデジタル1種類。RendererへWatchFaceを登録し、IDで切り替えられます。
切り替え時に旧キャッシュを解放し、新しい初期化が失敗したら旧WatchFaceの直接描画を試みます。
通常の文字盤選択UIはありません。RendererはUIタスクが操作し、オブジェクトの大きな領域は静的に配置して
8KiBのUIスタックを圧迫しないようにしています。

作業4ではDisplayDataSourceからサービスの最新スナップショットを返し、電池取得などの期限を指定します。
更新通知はUIタスクから `AppRuntime::dataChanged()` で渡します。
WatchFaceの分境界期限はRuntimeの64bit単調時刻の期限へ接続済みです。
時計が隠れている一覧と画面OFF中は時計だけの期限を無視し、復帰時に再取得します。

USB監視・入力ポーリングだけでは再描画しません。
dirtyまたは表示期限がある場合だけRendererを呼び、静止中のレイアウトも省略します。
周期超過時の作業2修正（処理前の期限をwaitで先送りしない、最低1tick待機）を維持しています。

## 描画とリソース

M5GFX所有のRGB565フレームバッファへ直接描画し、通常版に中間の全画面スプライトはありません。
時計5要素、一覧5行、ヒント、通知の計12要素に対し、FramePlanは固定32要素です。

1. 全レイヤーの旧矩形・新矩形・内容を計画する。
2. 消去領域だけでなく、新しい描画が重なる要素にも再描画を伝播する。
3. 消去をすべて終えてから、時計→一覧→ヒント→通知の順に描く。
4. 転送はM5GFXのstartWrite/endWriteでまとめる。

非表示要素も空矩形として登録し、消し残しを防ぎます。画面切り替え・復帰・通知の出現/消去・
WatchFace切り替えでは全面再描画します。
容量超過時は診断を出し、容量に関係なく全viewのpaintを実行する全面描画に退避します。
満杯の配列に再登録して欠落を繰り返す経路は使いません。

時刻文字だけを内部RAMの小さなスプライトにキャッシュします。確保失敗時は直接描画し、
毎フレームの動的確保を避けます。

固定日本語はGenShinGothic 28pxのVLWフォントを埋め込んで描画します。
元の2.3MiBをそのまま載せず、`tools/build_font.py` がASCII・かな・UIが使う約物と、
`src/` に現れる非ASCII文字だけを残した約147KiBの部分集合 `src/ui/fonts/GenShinGothic28.vlw` を作ります。
生成物はリポジトリに含め、ESP-IDF側の `EMBED_FILES` とPlatformIOの `board_build.embed_files` の
両方で参照します（PlatformIOがアセンブリを生成し、IDFのコンポーネントがそれをリンクします）。

読み込みは `ui/VlwFont.*` が一度だけ行います。`setFont()` はM5GFXが持つランタイムフォントを
破棄するため、VLWフォントとデータ参照はこちら側で所有し、他フォントと自由に切り替えられるようにしています。
読み込みに失敗した場合はlgfxJapanGothic_24へ退避し、一覧の表示自体は止めません。
部分集合の外の文字と不正UTF-8は `?` へ置換します。任意Unicodeは保証しません。
文字集合を変えたとき（UIの文言を増やしたときを含む）は `build_font.py` を実行し直します。
仕組み自体は日本語専用ではなく、別言語のフォントに差し替える場合も同じ経路を使います。

## PC検証とビルド

```powershell
python tools/build_font.py --source <元フォント.vlw> --check
python tools/test_runtime.py
python -m unittest discover -s tests -v
pio run -e m5stopwatch
python tools/verify_build.py
pio run -e m5stopwatch-render-check
python tools/verify_build.py --environment m5stopwatch-render-check
pio run -e m5stopwatch-diagnostics
python tools/verify_build.py --environment m5stopwatch-diagnostics
```

元のGenShinGothic 28px VLWはリポジトリに含めません。`build_font.py` は `--source` で
元フォントの場所を必ず指定します（既定値はありません）。
`--check` は手元の元フォントから作り直した結果と埋め込み済みの部分集合を比較するだけで、
元フォントがない環境では省略します。

ビルドは環境ごとに順番に実行します。`verify_build.py` はSDK、4MiB上限、MultiFirm固定版・
パーティション、hostイメージ、install-hostのローカル検査に加え、診断文字列が正しい環境にだけ含まれることを検査します。

PCテストは作業2回帰、スワイプ境界、選択循環、円形安全領域、当たり判定、補間の時間依存、
通知期限、分境界、静止/非表示/消灯時の抑制と復帰を確認します。
FramePlanは3,000フレームの矩形・重なり・消去・容量超過を独立した全面描画とピクセル比較します。
これはM5GFXでの文字・円・転送の実機検証を代替しません。

## 実機確認手順

導入は[作業1のinstall-host手順](../task1/product-build.md)に従います。
通常uploadは使用せず、以下のアプリ単体イメージを選びます。

| 環境 | イメージ | 用途 |
|---|---|---|
| 通常版 | `.pio/build/m5stopwatch/firmware.bin` | 操作・消灯・不明表示 |
| 描画検証版 | `.pio/build/m5stopwatch-render-check/firmware.bin` | ピクセル比較・検証用時計・性能集計 |
| 過負荷診断版 | `.pio/build/m5stopwatch-diagnostics/firmware.bin` | 40ms負荷、idle_cpu1、WDT回帰 |

1. 通常版で起動、MultiFirmレイアウト、240MHz、表示サイズを確認する。起動ログの
   `[Font] GenShinGothic28 glyphs=...` と、時計・一覧の日本語、円形画面端、選択色を目視確認する。
   一覧のアプリ名がGenShinGothic 28pxで描かれ、行が名前だけになっていることを確認する。
2. 時計からA/B、APPS、上ドラッグで一覧を開く。しきい値未満では時計へ戻ること、
   5項目の循環と連打、全項目の決定、一覧両端、ドラッグ後のタップ抑止を確認する。
3. 上下遷移中・通知中・ドラッグ中にホームを実行する。
   保持中の二重発火や、解放後に遅れて一覧へ戻る動きがないことを確認する。
4. 時計と一覧で30秒消灯を確認する。最初の復帰タッチは解放まで消費され、
   A/Bは通常どおり処理されること、A+Bは時計へ戻ることを確認する。
   USB抜き差しで不要な点灯・描画が起きず、ボタン/接触保持中は消灯しないことも確認する。
5. 描画検証版を導入し起動ログを保存する。起動時の自動検証で `[Verify] ... result=PASS` と
   `mismatches=0` を確認する。`UNVERIFIED` は合格ではない。
   元の24パターン、往復、5行、長い日本語、通知、復帰、WatchFace差し替え、
   キャッシュ無効化、容量超過を実行する。検証後は時計へ戻る。
6. 描画検証版の時計は2026-09-19 09:41を基点とする合成データで、単調時刻に従い進む。
   電池82%も検証値であり、実際のRTC/電池値ではない。分更新と復帰時の更新を確認する。
7. 描画検証版で、時計↔一覧のドラッグ往復と一覧スクロールをそれぞれ60秒以上続ける。
   60秒ごとの `[RenderDiag]` を保存する。区間内はなるべく指を止めず、
   描画時間と描画完了間隔の平均・最大・p95上限・33.3ms超過数・fpsを別々に読む。
   初期描画・単発更新は `single-draw` として分けて集計する。
8. 一覧の無操作区間では `layouts=0 paints=0` を確認する（通知終了・補間完了後から）。
   30秒で消灯するため、必要なら消灯を含めた静止区間として記録する。
   時計では分更新の単発描画を許す。消灯中は表示用更新を行わない。
9. 数分間の反復操作前後で内部RAM/PSRAM空き・最大連続領域、stack_freeを比較する。
   起動検証の `lifecycle` ログでも16回のキャッシュ解放・再確保前後を確認する。
10. 過負荷診断版で60秒以上操作し、5秒ごとのidle_cpu1が正、WDT・再起動・操作不能がないことを確認する。
    最後に通常版へ戻す。

### 計測値の読み方

`p95_upper` は1ms幅ヒストグラムの95パーセンタイル上限です。最終ビンは `>255000` となります。
平均・最大・33.3ms超過数はマイクロ秒の実測値から計算します。
`n=0` の行はサンプルなしで、p95等の数値は評価に使いません。
fpsは同種の連続描画ペア数÷ペア間隔合計です。指を止めた時間を含むと性能値として解釈できないため、
操作シナリオと継続時間を併記します。過負荷診断版の値を通常動作の性能に混ぜません。

`sampled-input-to-end` は意味イベントをサンプルした時点から転送終了まで、
`wake-request-to-end` は復帰要求から転送終了までです。
物理動作の開始からサンプリングまでの待ち時間は含まれません。
入力100ms・復帰300msの体感を含む検証には目視や動画も併用します。
各60秒区間を全体計画6.3節の30fps超・定常間隔33.3ms以内と比較し、未達は記録します。

結果は[作業3の検証記録](task3-validation.md)へ追記します。
